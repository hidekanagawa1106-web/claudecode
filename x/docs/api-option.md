# X API を使う場合（未導入・検討メモ）

現在は**API を使わない運用**です。このファイルは、導入するとしたら何が変わるかの
調査結果。2026年8月時点の情報。

---

## 一番大きいのは「投稿の自動化」ではなく「読み取り」

### 測れていない3指標が、そのまま取れる

X API の `non_public_metrics` は、**自分の投稿について**この3つを返します。

```json
"non_public_metrics": {
  "impression_count": 5432,
  "url_link_clicks": 89,
  "user_profile_clicks": 156
}
```

`url_link_clicks` と `user_profile_clicks` は、**いま `posts.csv` で全行が空になって
いる列そのもの**です。1stリプも自分の投稿なので、`reply_impressions` も同じ
呼び出しで取れます。

→ **`funnel.md` の2段ファネルが初日から完全に埋まります。**
「10本溜まるまで導線の判断は保留」という制約が消えます。

取得には OAuth のユーザーコンテキスト認証が要ります（自分のアカウントのみ。
他人の投稿には使えません）。

### サンプル数が11本 → 数百本になる

**現在の最大の弱点は、実測サンプルが過去11本しかないこと。**
「失敗ドラマで40倍」「作業か姿勢かで14倍」も、根拠は2本ずつの比較です。

競合20アカウント × 直近20投稿を週次で取れば、**1回で400本**。
自分で30本投稿するのに10日かかるところが、$2で400本になります。

`winners.md` の仮説を**他人のデータで検証できる**ようになるのが本質的な価値です。

## 工数の削減（副次的）

| 工程 | 現在 | API |
|---|---|---|
| 夜の実績記録 | スクショ→`/x-review`（5分） | 自動。**一番飛ばしやすい工程が消える** |
| バズ判定→1stリプ | 手動で様子見（5分） | 閾値で自動判定。**寝ている間の伸びも拾える** |
| 競合スカウト | 手動で持ち込み（週20分） | 自動収集 |
| 朝の投稿 | コピペ×3（2分） | 予約投稿 |

**バズ判定は人間より正確になります。** 現在は「反応が付き始めてから1〜2時間」を
感覚でやっていますが、「投稿30分後にインプレッションが直近中央値の1.5倍を超えたら」
という閾値で判定できます。

他に取れるもの: 投稿時刻とインプレッションの相関（現在 `slot` が「不明」ばかり）、
フォロワー増の投稿への帰属、自分の投稿へのリプの自動検知。

## API を使っても自動化しないもの

- **他人へのリプライ** —— 2026年の制限で、自動リプは**相手が先にそのアプリを
  メンションしている必要**があります。実質不可
- **自分の投稿へのリプ返信** —— 技術的には可能だが、AI生成リプは**X社の事前書面
  承認**が必要。手動を維持
- **スクレイピング・ブラウザ自動化** —— 規約違反（永久凍結対象）。選択肢外

**自分のコンテンツの予約投稿は問題ありません**（「最も基本的な自動化」と明記されて
います）。bot ラベルが要るのは大規模自動化・bot駆動アカウントで、予約投稿は
該当しません。

| 操作 | 単価 |

| リンクなし投稿 | $0.015 |

## 導入するなら、この順番

**1. 読み取りだけ（$9/月）** —— 実績の自動記録 + 競合スカウト。
効果が最大で、**アカウントに何も書き込まないのでリスクがゼロ**。

**2. 投稿（$1.35/月）** —— 慣れてから。1日2分しか浮かないので急ぎません。

**3. 1stリプの自動化（$6/月）** —— 閾値の妥当性が実データで見えてから。

実装するとしたら `x_metrics.py`（実績取得）と `x_scout_api.py`（競合収集）の2本。
**APIキーが用意でき次第、着手できます。**

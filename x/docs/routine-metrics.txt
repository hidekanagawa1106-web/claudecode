## 1. 取得

```
pip install -q requests requests-oauthlib
python x/x_metrics.py
```

**pip install を飛ばさないでください。** セッションのコンテナは毎回まっさらで、
`requests-oauthlib` は標準では入っていません（pandas は入っています）。
環境のセットアップスクリプトに入れてあれば不要ですが、二重に実行しても
数秒で終わるので、ここでは毎回叩く前提にしています。

3日前のJST1日ぶんだけを取ります。**取得済みならAPIを呼ばずに終了する**ので、
「取得済みです」と出たらそれで正常です。手順2へ進んでください。
「投稿はありませんでした」も正常です（その日は投稿していないだけ）。

**引用リポストが1日3〜5本あるのは正常です。** Hideさんの運用方針で、
引用元に拾ってもらってフォロワーを増やすのが狙いです。
**「引用RTのimpが低い」という指摘はしないでください。** 測る指標が違います。

**`link_clicks` と `reply_impressions` が空なのは正常です。**
返信はAPI側で除外しているので取れません（交流リプまで課金対象になるため）。
**導線は月次のエクスポートCSVで測る**方針なので、ここで欠けていても
問題ありません。「導線が取れていない」と報告しないでください。

### 出力を要約しないこと

**スクリプトが出した本文を、そのまま全文貼ってください。** 表にまとめたり、
「◯◯の話」と要約したりしないこと。**Hideさんは本文そのものを読みたいので、
1行目だけの一覧では用が足りません。**

投稿ごとにこの形で出します（スクリプトの出力そのままです）。

```
==========================
2026-08-13 06:10 朝
imp 2,358  ♥18  RT0
返6  BM3  プロフ6
型 型3/型5 観察
https://x.com/i/status/xxxx
--------------------------
（本文をここに全文。省略しない）
```

**この幅のままにしてください。** スマホで横スクロールせずに読める幅に
合わせてあります。表に組み替えたり、1行にまとめたりしないこと。

**エラーが出たら、そこで止めて内容をそのまま報告してください。**
キーの不備・課金の問題・API仕様の変更のいずれかなので、こちらで直します。
**リトライや回避策の自作はしないこと。** APIは呼ぶたびに課金されます。

## 2. 在庫と突き合わせる（**ここが一番大事**）

```
python x/x_match.py
```

投稿された本文を、`x/stock.md` の下書きと類似度で照合します。

**Hideさんは下書きをそのまま使いません。必ず手を入れてから投稿します。**
実際、これまでの3本すべてが書き換えられていました（14行→10行の削り、
締めの全面差し替え、セリフへの「！」追加）。**文字列の完全一致は期待できません。**

スクリプトが出す判定の読み方:

| 出力 | やること |
|---|---|
| **在庫に該当なし**（55%未満） | Hideさんが自分で思いついた投稿。在庫は触らない |
| **◯◯と92%以上一致** | ほぼそのまま。使用済みへ移すだけ |
| **◯◯と55〜92%一致** | **手を入れて投稿された。差分の理由を言語化する** |

### 差分が出たときにやること

**1. 使用済みへ移す。** `stock.md` の該当項目を「使用済み」セクションへ。
日付・インプレッション・「Hideさんが◯箇所修正」を添えます。

**2. 差分の理由を `voice.md` の「削り方」に反映する。** これが本題です。

- **既存の項目に当てはまるなら、実例を1つ足すだけ。** 番号は増やさない
- **新しい傾向なら番号を振って追加する**
- **1回の差分で一般化しないこと。** 同じ直され方が2回出てから書きます。
  1回目は「観測中」として `winners.md` に書き留めるだけにしてください

**理由を「短くなった」で済ませないでください。** 何が削られ、代わりに何が
入ったのかまで書きます（例: 帰結が削られて原因が入った、決め台詞の言い換えが
削られて一段広い一般化が入った）。

**3. 判定に迷ったら、書き換えずに報告してください。** 似ているだけの別物を
「使用済み」にすると在庫が消えます。

## 3. 改善点の診断

```
python x/x_diag.py --days 7
```

直近7日の投稿を、**型ごとに別の物差しで**診断します。

**全型に共通のチェックリストはありません。** 型が違えば効く要素も違い、
「他人が登場」ですら型4では0.1倍（入れると下がる）でした。

| | 型3/型5 | 断言 | 型4 |
|---|---|---|---|
| 他人が登場 | 2.2倍 | 3.8倍 | **0.1倍** |
| 年齢 | 5.7倍 | 3.5倍 | 0本 |
| 箇条書き4つ以上 | **0.3倍** | — | — |

**型2・型4・型8・型11は本数不足で診断されません。** 「診断できません」と
出たらそれが正常です。**要素が欠けているとは報告しないでください。**

**スクリプトの出力をそのまま貼ってください。** そのうえで、
**同じ指摘が2日以上続いた場合だけ**一言添えます（1日ぶんは偶然の範囲）。

**「要素を足せば伸びる」と書かないでください。** 型による差は2倍程度で、
月による差は300倍でした。要素は下限を上げるだけです。

**書くことが無ければ書かないでください。** 毎日何か足そうとすると、

毎朝6:30（JST）の定期実行です。前日までに記録された実績を読んで、学びを更新してください。

**このRoutineはX APIを呼びません。** 実績の取得は GitHub Actions が6:00に
済ませて `posts.csv` にコミットしています（APIキーはGitHub Secretsにあり、
こちらには渡っていません）。

## 1. 最新を取り込む

```
git pull origin main
```

Actionsが6:00にコミットしているはずです。**新しい行が無ければ、それは
「3日前に投稿が無かった」ということなので正常です。** その場合は
「記録対象なし」とだけ報告して終了してください。

**`x/x_metrics.py` を自分で実行しないでください。** キーが無いので失敗しますし、
仮に通っても二重取得になります。Actionsが失敗している場合は、その旨を
報告するだけにしてください（こちらで直します）。

## 2. 集計

```
python x/x_review.py --last 20
```

出力の読み方は `.claude/skills/x-review/SKILL.md` の手順2と同じです。
**インプレッションから読み始めないでください。** 導線のブロックから読みます。

## 3. 言語化（ここが本体）

`x/docs/winners.md` を読んでから、**新しく分かったことがある場合だけ**追記します。

- 既存の記述と矛盾する結果が出たら、**古い記述を消さずに「◯月◯日時点で反転」と併記**
- **1本の結果で結論を出さない。** 同じ型が3本溜まるまでは「観測中」と書く
- **型の順位から結論を出さない。** 型はインプレッションをほとんど説明しません
  （月内の相対中央値で型1・型2・型3は横並び。`winners.md` の該当節を参照）

**書くことが無ければ書かないでください。** 毎日何か足そうとすると、
このファイルは薄まります。

## 4. 在庫の更新

記録した投稿が `x/stock.md` の在庫から出たものなら「使用済み」へ移してください。
Hideさんが自分で思いついて投稿したものなら、在庫は触りません。

## 5. コミット

変更があれば、`x/posts.csv` と更新したドキュメントをコミットしてプッシュ。
変更が無ければ何もしないでください。

## 報告

**3行で足ります。**

- 取得した投稿の本数と、目立った数字1つ
- winners.md に追記したか（したなら1行で内容）
- 交流リプの取得件数（コスト把握のため）

**数字の解説は要りません。** Hideさんも同じ表を見ています。

# 日経225 大引け坊主スクリーニング 前場前タスク

平日の前場前（例: 8:30頃）に実行する、日経225構成銘柄を対象とした
「大引け坊主」（陽線・陰線とも上下ヒゲがほぼない実体のみの足）スクリーニングの仕様。

**現時点ではRoutine未登録。** 下記「前提条件」を満たすまでは `/schedule` による
日次自動化を行わないこと（初回は手動実行で動作確認してからにする）。

## 前提条件（未整備）

このタスクは `screen_marubozu.py` というスクリプトの実行を前提としているが、
本リポジトリには現時点で以下が存在しない。

- `screen_marubozu.py`（J-Quants APIから日足OHLCVを取得し、大引け坊主判定・
  RSI等のクオンツ条件判定を行うスクリプト本体）
- `nikkei225_codes.csv`（日経225構成銘柄の証券コード一覧）
- 環境変数 `JQUANTS_API_KEY`（J-Quants APIの認証キー）

これらが揃うまで、下記プロンプトを実行しても「事前確認」の段階で停止する。
`screen_marubozu.py` は別途配置が必要。

## プロンプト本文（Routineに設定する想定の内容）

あなたは日本株スイングトレードの前場前スクリーニングを実行するアシスタントです。
以下の手順で `screen_marubozu.py` を実行し、結果をレポート形式で報告してください。

### 事前確認

1. 環境変数 `JQUANTS_API_KEY` が設定されているか確認する。未設定ならその旨を報告して停止する。
2. `screen_marubozu.py` が現在のプロジェクトフォルダに存在するか確認する。
   存在しない場合は、その旨を報告して停止する（別途配置が必要）。
3. `requests` と `pandas` がインストールされているか確認し、なければ
   `pip install requests pandas` でインストールする。

### 銘柄コード一覧の準備

4. `nikkei225_codes.csv` が既にプロジェクトフォルダにあるか確認する。
   - あれば、更新日を確認し、直近1ヶ月以内でなければ最新の日経225構成銘柄
     リストをWeb検索で調べ、内容が変わっていないか確認する（年1回程度の定期見直しがあるため）。
   - なければ、信頼できるソース（日本経済新聞、JPX関連情報など）から
     現時点の日経225構成銘柄コード一覧をWeb検索で調べ、1列目に証券コードを
     入れた `nikkei225_codes.csv` を作成する。

### スクリプト実行

5. 次のコマンドを実行する。
   ```
   python screen_marubozu.py --codes nikkei225_codes.csv
   ```
6. `KeyError` 等でカラム名に関するエラーが出た場合は、エラーメッセージに
   含まれる実際のレスポンス列名を確認し、スクリプト内の `COLUMN_ALIASES`
   にその列名を追加して再実行する。
7. その他のエラー（認証エラー、レート制限エラー等）が出た場合は、
   エラー内容をそのまま報告し、対応方針（待機して再実行、契約プランの
   確認など）を提案する。

### 結果のレポート

8. 出力された `marubozu_candidates.csv` の内容を読み込み、以下の形式で報告する。

   - **quant_all_pass = True の銘柄**：最有力候補として個別に列挙
     （銘柄コード、パターン(陽/陰の大引け坊主)、終値、RSI）
   - **quant_all_pass = False だが大引け坊主だった銘柄**：参考情報として
     まとめて列挙（どの条件を満たしていないかも添える）
   - 該当銘柄がゼロの場合は、その旨を明確に報告する

9. レポートの最後に、必ず以下の注意書きを添える。
   > 「材料の裏付け」（金利・為替・受注・政策など）は自動判定していません。
   > 候補銘柄について、決算・ニュース・材料面を個別に確認してください。
   > また、これは候補リストであり、実際のエントリーは場中に順張り4条件
   > （ORB・VWAP・出来高・連動銘柄）を満たすかどうかで別途判断してください。
   > 1日に複数銘柄へ手を出さないというルールも踏まえ、報告する候補は
   > 優先順位をつけて提示してください（quant_all_pass=Trueかつ出来高倍率が
   > 高いものを上位に）。

## 補足

- 初回実行時はエラーが出る可能性が高いので、手動で1回実行して
  動作確認してから `/schedule` での自動化に進むことをおすすめします。
- 日経225の構成銘柄コード一覧は年1回程度見直されるため、月1回程度
  最新かどうかの確認を組み込んでいます。

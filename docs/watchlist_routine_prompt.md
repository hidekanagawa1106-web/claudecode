# 日経225ウォッチリスト運用 実行依頼プロンプト（Claude Code用）

以下をそのままClaude Codeに貼り付けて使う想定。
`build_universe.py` / `screen_daily.py` / `review.py` を同じプロジェクトフォルダに
置いた状態で実行する。

実行タイミング：
- `screen_daily.py` は平日の大引け後（例: 15:30頃）に毎日実行
- `build_universe.py` は月1回程度（月初など）に実行
- `review.py` は記録が20件たまったタイミングで都度実行

毎日自動化したい場合は、下記プロンプトを `/schedule` で日次タスクとして登録する。

---

## プロンプト本文（ここからコピー）

あなたは日本株スイングトレードの日次ウォッチリスト運用を管理するアシスタントです。
以下の手順で実行し、結果をレポート形式で報告してください。

### 事前確認

1. 環境変数 `JQUANTS_API_KEY` が設定されているか確認する。未設定なら報告して停止する。
2. `build_universe.py` / `screen_daily.py` / `review.py` がプロジェクトフォルダに
   存在するか確認する。存在しなければ報告して停止する。
3. `requests` と `pandas` がインストールされているか確認し、なければインストールする。

### ステップ1: ユニバースの鮮度チェック（月1回相当）

4. `universe.csv` が存在するか確認する。
   - 存在しない、または `updated_date` が30日以上前の場合:
     a. `nikkei225_codes.csv` が最新か確認する（無ければWeb検索で日経225構成銘柄
        コード一覧を調べて作成する。年1回程度の定期見直しがあるため、既存のもの
        も30日以上前なら中身が変わっていないか確認する）
     b. `python build_universe.py --codes nikkei225_codes.csv --max-price 5000 --max-universe 30`
        を実行してユニバースを更新する
   - 30日以内に更新済みなら、このステップはスキップしてよい

### ステップ2: 日次スクリーニング＋記録

5. 次のコマンドを実行する。
   ```
   python screen_daily.py --universe universe.csv --log picks_log.csv --top-n 5
   ```
6. `KeyError` 等のカラム名エラーが出た場合は、エラーメッセージの実際の列名を確認し、
   スクリプト内の `COLUMN_ALIASES` に追加して再実行する。
7. 認証エラー・レート制限エラーが出た場合は、内容をそのまま報告し対応方針を提案する。

### ステップ3: レポート

8. `screen_daily.py` の出力から、本日選ばれた銘柄（最大5件）を次の形式で報告する。
   - 銘柄コード／ドライバー分類／パターン(陽・陰の大引け坊主)／RSI／quant_all_pass
   - ドライバーが特定の1〜2種類に偏っていないかも一言添える
9. 記録済みサンプル数が20件以上になったタイミングでのみ、次を実行して結果を報告する。
   ```
   python review.py --log picks_log.csv --min-samples 20
   ```
   20件未満の場合は実行不要（現在のサンプル数だけ報告する）。
10. レポートの最後に、必ず以下を添える。
    > 「材料の裏付け」は自動判定していません。候補銘柄は決算・ニュース・材料面を
    > 個別に確認してください。ここに出た銘柄は「翌日ウォッチする候補」であり、
    > 実際のエントリーは場中に順張りの必須2条件（ORB上抜け・前日終値時点の
    > 日足MA25の上）を満たすかどうかで別途判断してください。VWAP・場中の出来高・
    > 連動銘柄は v3 で参考項目に降格しました。
    >
    > review.py の結果は参考情報です。フィルタ条件やロジックを変更するかどうかは
    > 私（Hide）が判断します。Claude Code側でロジックを自動的に書き換えることは
    > しないでください。

## 補足

- `review.py` の結果を見てロジックを変えたくなった場合も、まずは変更案を提示して
  もらい、こちらで承認してから `screen_daily.py` を修正する運用にすると、
  禁止事項6「エントリー後に理由を後付けする」と同じ轍を踏まずに済みます。
- `screen_daily.py` が記録する値動きは日足ベース（前日終値→翌日始値のギャップ率、
  始値→終値の当日変化率）です。ORB（寄り付き後の分足）まで含めた検証をしたい場合は、
  別途分足データの取得手段が必要になります。
- `driver_tags.csv`（code,driver の2列）を用意しておくと、ユニバース内の
  ドライバー分類（半導体・金融・防衛・内需・その他など）が反映され、
  同日に偏った銘柄ばかり選ばれるのを防げます。未用意の銘柄は "unclassified" として
  扱われ、優先度は下がりますが除外はされません。

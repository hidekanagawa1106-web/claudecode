平日朝8:00（JST）の定期実行です。日本株の朝の統合ブリーフィングを出してください。

## 手順

### 1. 朝のジョブを実行する

python morning.py

74銘柄をJ-Quantsから取得するので5〜10分かかります。

うまく動かない場合:
- ModuleNotFoundError が出たら pip install -r requirements.txt を実行してから再試行してください（通常はセッション開始時のフックが済ませています）
- 環境変数 JQUANTS_API_KEY が未設定なら morning.py は即座に落ちます。その場合は「実行環境に JQUANTS_API_KEY が設定されていません」と報告して終了してください。キーを推測したり、別の取得元を探したりしないでください

### 2. 出力をそのまま報告する

morning.py はすでに読み手向けの形で出力します。構造を組み替えないでください。
以下の見出しの順序と中身を保ったまま、そのまま報告してください。

- 今日の地合い — 1〜3行
- ウォッチする銘柄 — 各銘柄の理由（決算・トレンド・出来高・RSI）を省略しない
- 見送り推奨 — ルールに触れる銘柄と、その理由。ここは必ず全件そのまま載せてください
- 材料が出ている銘柄 — MA25の下。順張り対象外
- 本日決算発表

長すぎる場合に削ってよいのは「絞り込みの経過」だけです。
銘柄名・価格・理由の行は削らないでください。判断に必要な情報です。

見送り推奨は「良い銘柄だが今日は入れない」という情報です。
勝手に候補へ格上げしたり、逆に省略したりしないでください。

### 3. 記録を push する

picks_log.csv に変更があれば、main ブランチに反映してください。

git add picks_log.csv
git commit -m "Record picks"
git pull --rebase origin main
git push origin HEAD:main

毎回まっさらなコンテナで動くため、push しないとその日の候補が消えます。
記録が貯まらないと、朝スコアが有効だったかを後から検証できなくなります。
pull --rebase を挟むのは、開発セッションが同じファイルを触ることがあるためです。

## 報告に必ず添えること

- 「材料の裏付け」は自動判定していません。候補銘柄は決算・ニュース・材料面を個別に確認してください。
- ここに出た銘柄は「翌日ウォッチする候補」であり、実際のエントリーは場中に順張り4条件（ORB・VWAP・出来高・連動銘柄）を満たすかどうかで別途判断してください。
- 8:00 JST は 19:00 ET（夏時間）で、米国の時間外取引は 20:00 ET まで続きます。引け後に決算が出た銘柄は、この時点では動き切っていない可能性があります。

## 制約

- 休場日かどうかは morning.py が冒頭で判定して出力します（東証のカレンダーを直接参照しています）。「東証: 休場日」「東証: 非営業日」と表示され、スクリプトがそこで終了した場合のみ、その旨だけ報告して終わってください。
- 「東証: 営業日」と出たら、pick_date が前回と同じでも必ず全文を報告してください。pick_date が前回と同じことを休場日の根拠にしないでください。日足は前営業日までしか無いため、月曜の朝は必ず金曜の日付になります。2026-08-03(月)にこの誤判定で営業日の配信を落としました。
- エラーが出た場合は、原因を報告するだけにしてください。自分で修正しないでください。
- フィルタ条件やスコアリングのロジックを自動的に書き換えないでください。変更するかどうかの判断はHideさん本人が行います。数値がおかしいと感じた場合も、指摘するにとどめてください。

## 補足（このシステムの前提）

- 朝スコアは銘柄スコアに加算していません。候補一覧に併記するだけで、順位付けには使っていません。マクロとテクニカルは互いのゲートにせず、2本のトラックとして並べる設計です。
- 商社・海運・自動車の3グループは60営業日の実測に基づいています。半導体・メガバンク・防衛・保険の4グループはニューストピックを含むため過去再現ができず、閾値と感応度は未検証です。
- 保険と防衛・重工は、数値指標だけでは閾値に届かない構成です。ニュースが出ない日には発火しません。仕様通りの挙動です。

平日朝8:00（JST）の定期実行です。日本株の朝のブリーフィングを出してください。

## 手順

### 1. 朝のジョブを実行する

python briefing.py

watchlist.csv の15銘柄をJ-Quantsから取得します。2〜4分かかります。

うまく動かない場合:
- ModuleNotFoundError が出たら pip install -r requirements.txt を実行してから再試行してください（通常はセッション開始時のフックが済ませています）
- 環境変数 JQUANTS_API_KEY が未設定なら briefing.py は即座に落ちます。その場合は「実行環境に JQUANTS_API_KEY が設定されていません」と報告して終了してください。キーを推測したり、別の取得元を探したりしないでください

### 2. 出力をそのまま報告する

briefing.py の標準出力を、**改行も含めてそのまま貼ってください。**

これは「要約せずに」という以上の意味です。実際に 2026-08-05 の配信で、
1銘柄ぶんの情報が

  7011 三菱重工業 4,091円 MA25+6.7% 40.9万円｜見送り理由:…｜マクロ:…｜ニュース:…

のように ｜ で連結された1行に潰されて届きました。スクリプト側は既に
1要素1行の箇条書きで出力しているので、**行を連結しないでください。**
読み手はスマホで読みます。どこで切れるかを探しながら読むことになります。

- 行を ｜ や / でつながない
- ● 決算 / ● マクロ / ● ニュース / ● トレンドと直近の値動き の見出しを消さない
- インデント（字下げ）をそのまま保つ
- 表形式に組み替えない

以下の見出しの順序と中身を保ったまま報告してください。

- 今日の地合い（要約）
- 前提1 前夜の海外市場 — 指標ごとの変化率。内訳・時間外・影響先まで
- 前提2 グループ別のマクロ — 7グループの朝スコアと項目ごとの内訳
- 前提3 今朝のニューストピック — 方向判定と、根拠になった見出し・一致した語
- 15銘柄の状態（一覧）— 15行すべて。1行も省略しないでください
- 順張りの土俵 / 押し目 / トレンド下向き / 見送り — 銘柄ごとに ● 決算 / ● マクロ / ● ニュース / ● トレンドと直近の値動き
- 本日決算発表

決算の欄は2通りに書き分かれます。どちらも省略しないでください。

- これから決算 — 「⚠ 次回決算は ○月○日 前後と推定（あとN日）」。5日以内は警告付き
- 決算が出た後 — 中身（営業利益YoY・進捗率・修正）／株価の反応（発表日と翌3営業日の
  ギャップ・終値・出来高倍率）／決算に触れた見出し

**このブリーフィングの主役は「前提1〜3」です。** ニュースとマクロは要約せず、
見出しと数字をそのまま載せてください。テクニカルは大きなトレンドの向きと
前日のローソク足だけに絞ってあるので、そこを膨らませる必要はありません。

**15銘柄は絞り込みの対象ではありません。** あらかじめ決めた固定リストなので、
「今日はこの3件だけ見ればよい」といった要約はしないでください。
15件すべての状態を報告するのがこのブリーフィングの目的です。

長すぎる場合に削ってよいものはありません。ニュース見出し・指標の変化率・
銘柄名・価格・トレンド・ローソク足の行は、すべて判断に必要な情報です。

RSI・出来高倍率・VWAP・ボリンジャー・ATRは意図的に出力していません。
場が開くまでに変わる指標で、買う瞬間に /entry-check で見るためです。
これらを補って報告しようとしないでください。

### 3. 記録を push する

watch_log.csv に変更があれば、main ブランチに反映してください。

git add watch_log.csv
git commit -m "Record daily watchlist state"
git pull --rebase origin main
git push origin HEAD:main

毎回まっさらなコンテナで動くため、push しないとその日の記録が消えます。
記録が貯まらないと、土俵ごとの成績を後から検証できなくなります。
pull --rebase を挟むのは、開発セッションが同じファイルを触ることがあるためです。

## 報告に必ず添えること

- 「材料の裏付け」は自動判定していません。決算・ニュース・材料面は個別に確認してください。
- このブリーフィングは日足の状態を並べたものであって、買いのサインではありません。実際のエントリーは場中に entry_check.py（/entry-check）で判定してください。
- 8:00 JST は 19:00 ET（夏時間）で、米国の時間外取引は 20:00 ET まで続きます。引け後に決算が出た銘柄は、この時点では動き切っていない可能性があります。

## 制約

- 休場日かどうかは briefing.py が冒頭で判定して出力します（東証のカレンダーを直接参照しています）。「東証: 休場日」「東証: 非営業日」と表示され、スクリプトがそこで終了した場合のみ、その旨だけ報告して終わってください。
- 「東証: 営業日」と出たら、pick_date が前回と同じでも必ず全文を報告してください。pick_date が前回と同じことを休場日の根拠にしないでください。日足は前営業日までしか無いため、月曜の朝は必ず金曜の日付になります。2026-08-03(月)にこの誤判定で営業日の配信を落としました。
- エラーが出た場合は、原因を報告するだけにしてください。自分で修正しないでください。
- watchlist.csv の銘柄を勝手に入れ替えないでください。ロジックやフィルタ条件も同様です。変更するかどうかの判断はHideさん本人が行います。数値がおかしいと感じた場合も、指摘するにとどめてください。

## 補足（このシステムの前提）

- 15銘柄は 2026-08-04 に確定し、2026-08-05 に1件入れ替えました（任天堂→安川電機。任天堂は200営業日のうち順張りの土俵に乗るのが4%しかなく、連動確認も効きませんでした）。売買代金が集まっている場所に居ることを優先し、半導体・AI関連を4枠（フジクラ・KOKUSAI・ソフトバンクG・村田製作所）にしています。選定理由は docs/watch-portfolio.md にあります。
- 「今日の土俵」は新しい判定ではなく、運用方針_v2 のどの節が適用されるかを書き出したものです。順張りの土俵=§3-1、押し目=§3-2、トレンド下向き=禁止事項1、見送り=§2イベントフィルタ／禁止事項2。
- 「押し目」は深さを問わない箱です。MA25から -2% の銘柄と -18% の銘柄が同じ見出しの下に並びます。深さで切る案（終値>MA75 / 乖離-8%以内）は2つとも実測が支持しなかったため、フィルタは足さずに MA25乖離を一覧と各行に出す形にしてあります。乖離の数字は省略しないでください。
- 朝に厚く出すのは前提情報（海外市場・マクロ・ニュース）で、テクニカルは大きなトレンドの向きと前日のローソク足だけに絞っています。RSI・出来高倍率などは場が開くまでに変わるため、買う瞬間に /entry-check で見る設計です。
- 朝スコア（マクロ）は銘柄の点数に加算していません。併記するだけで、順位付けにも使っていません。マクロとテクニカルは互いのゲートにせず、2本のトラックとして並べる設計です。
- ニュースは取得しますが採点していません。見出し6,569件で検証したところ翌日リターンとの相関は最大 r=0.16(p=0.22) でした。
- 商社・海運・自動車の3グループは60営業日の実測に基づいています。半導体・メガバンク・防衛・保険の4グループはニューストピックを含むため過去再現ができず、閾値と感応度は未検証です。
- 保険と防衛・重工は、数値指標だけでは閾値に届かない構成です。ニュースが出ない日には発火しません。仕様通りの挙動です。
- 良品計画は日経225の中で最大相関が 0.42 しかなく、§3-1 条件4「連動銘柄が同方向に動いているか」を判定できません。この銘柄だけは残り3条件で見る前提です。連動先は docs/peer-list.md にあります。
- 決算の次回予定日は、前年同期の開示日を364日ずらした推定値です。確定日ではありません。会社が発表日を前後させれば数日ずれます。

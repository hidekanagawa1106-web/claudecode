# 使い方（コマンド一覧）

## 1. エントリー判定（買いたいときに都度）

**チャート画像を添付して、次のいずれかを送る。**

```
/entry-check 8306
```

またはスラッシュコマンドを使わず、自然文でも起動する。

```
8306を買いたい
このチャートどう？
エントリーしていい？
```

画像は日足と分足の2枚があると精度が上がる。1枚でも動く。画像なしでも日足の判定だけは出る。

**渡すと良いもの**
- 銘柄コード（4桁、または `285A` のような形式）
- チャート画像（日足＋分足）
- 現在値（画像に写っていれば不要）

**返ってくるもの**
- 順張り4条件（ORB・VWAP・出来高1.5倍・連動銘柄）の充足状況
- 逆張り4条件（ボリンジャー-2σ・RSI30・出来高急増・反発の陽線）の充足状況
- 禁止事項7項目のうち該当するもの
- 決算・会合のイベントフィルタ
- 損切り・利確の推奨値と、その銘柄のボラティリティに対する妥当性
- 判定できなかった項目

**返ってこないもの**: 「買うべき」「見送るべき」という結論。最終判断は本人。

数値だけ欲しい場合はスクリプトを直接叩いてもよい。

```
python entry_check.py 8306 --price 3571
python entry_check.py 8306 --interval 3m   # 逆張り条件を3分足で見る（既定は5分足）
```

逆張り4条件は**場中のエントリータイミングを見る条件**で、朝のスクリーニングには使わない。
Yahooに3分足は無いため、1分足（7営業日分）から合成している。5分足は1ヶ月分そのまま取れる。

## 2. 取引の振り返り（決済したあと）

約定履歴の画像かCSV、または口頭で内容を伝えると起動する。

```
/trade-review
今日の取引を報告
決済したので振り返って
損切りになった
```

**必要な5項目**: 銘柄コード／エントリー日と価格／決済日と価格／株数／決済理由。
足りなければ聞き返す。発注した逆指値・指値、朝スコア、エントリー根拠もあると精度が上がる。

**返ってくるもの**
- 損益と保有営業日数
- ルール遵守の確認（順張り4条件・禁止事項・逆指値を動かさなかったか）
- **決済水準の検証** — 保有中の最大含み益／含み損、決済後の値動きから
  「損切りが浅すぎたか」「利確が早すぎたか」を数字で判定
- `trades.csv` への記録（同じ日・同じ銘柄は二重に記録しない）

スクリプトを直接叩く場合。

```
python trade_review.py --code 8306 --entry-date 2026-07-29 --entry-price 3480 \
  --exit-date 2026-07-30 --exit-price 3525 --shares 100 \
  --stop 3341 --target 3724 --reason 利確 --rule 遵守 --save

python trade_review.py --stats     # 累積の勝率・平均損益・§9の判定基準
```

## 3. 朝の統合ブリーフィング（平日 8:00 想定）

```
python morning.py
python morning.py --format brief    # ランキングと決算一覧だけの短縮版
```

3部構成で返る。

1. 前夜の海外市場 — 急変検知・グループ別の朝スコア・時間外の動き
2. 日足のテクニカル候補 — 順張りトラックの上位5銘柄
3. 材料 × テクニカルの交差 — 材料が来ているグループの中でテクニカルも整っている銘柄

候補一覧には所属グループの**マクロ（朝スコア/閾値）を併記**する。これは材料として
並べているだけで、銘柄の点数には加算していない。マクロとテクニカルは互いのゲートに
せず、2本のトラックとして扱う。グループを持たない単独銘柄は `-` になる。

同じ日に2回実行しても `picks_log.csv` は重複しない。

**注意**: 8:00 JST は 19:00 ET で、米国の時間外取引は 20:00 ET まで続く。引け後に決算が出た
銘柄はこの時点で動き切っていない可能性がある。冬時間はさらに1時間ずれる。

前夜の海外市場だけを見たい場合。

```
python overnight.py
python overnight.py --asof 2026-07-31   # 過去日の再現（時間外はスキップされる）
```

## 4. ユニバース更新（月1回程度）

```
python build_universe.py --codes nikkei225_codes.csv --max-price 5000 \
  --min-turnover 120 --keep-codes keep_codes.csv --max-universe 50
```

225銘柄を全部叩くので8〜9分かかる。日経225の構成銘柄が入れ替わったときは
`nikkei225_codes.csv` の更新が先。

## 設定ファイル

| ファイル | 中身 | 変更する場面 |
|---|---|---|
| `driver_map.yaml` | 連動グループの朝スコア・ニューストピック・感応度 | 指標や感応度を変えたいとき |
| `driver_tags.csv` | 銘柄 → ドライバー → 連動グループ | 分類を変えたいとき |
| `keep_codes.csv` | 条件を満たさなくても残す銘柄 | ウォッチ対象を足したいとき |
| `universe.csv` | 現在のユニバース74銘柄 | 通常は build_universe.py が生成 |
| `trades.csv` | 実売買の記録 | trade-review スキルが追記 |

### driver_map.yaml の項目に付けられるもの

| キー | 意味 |
|---|---|
| `ticker` | Yahooのシンボル。複数書くと平均で採点する |
| `感応度: -1` | その指標の**上昇がそのグループにとって逆風**（自動車の米10年債など） |
| `採点: false` | 変化率は表示するが**合計には入れない**。検証で効果が確認できていない指標を、消さずに材料として残すために使う |
| `急変閾値` | この%を超えたら★急変。平均だけでなく個別ティッカーも見る。全項目、発動率が10%前後になるよう実測から較正済み |

`driver_tags.csv` と `keep_codes.csv` を変えた場合、ユニバースの顔ぶれ自体は
`build_universe.py` を回さないと変わらない。分類やタグだけの変更なら再取得は不要。

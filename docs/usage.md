# 使い方（コマンド一覧）

## 0. 初回セットアップ

```
pip install -r requirements.txt
```

pandas・numpy・requests・PyYAML・openpyxl が要る。openpyxl は earnings.py が
JPXの決算発表予定日(Excel)を読むのに使う。

## 1. エントリー判定（買いたいときに都度）

**チャート画像を添付して、次のいずれかを送る。**

```
/entry-check 8306
```

またはスラッシュコマンドを使わず、自然文でも起動する。

```
8306を買いたい
このチャートどう？
エントリーしていい？
```

画像は日足と分足の2枚があると精度が上がる。1枚でも動く。画像なしでも日足の判定だけは出る。

**渡すと良いもの**
- 銘柄コード（4桁、または `285A` のような形式）
- チャート画像（日足＋分足）
- 現在値（画像に写っていれば不要）

**返ってくるもの**
- 順張りの必須2条件（ORB上抜け・日足MA25の上）の充足状況
- 参考項目（VWAP・場中の出来高・連動銘柄）— 判定には使わない
- 逆張り4条件（ボリンジャー-2σ・RSI30・出来高急増・反発の陽線）— **日足で見る**
- 禁止事項（下降トレンドの途中で買う）の該当有無
- 決算・会合のイベントフィルタ
- 損切り・利確の推奨値と、その銘柄のボラティリティに対する妥当性
- 判定できなかった項目

**返ってこないもの**: 「買うべき」「見送るべき」という結論。最終判断は本人。

数値だけ欲しい場合はスクリプトを直接叩いてもよい。

```
python entry_check.py 8306
python entry_check.py 8306 --price 3571    # 今の株価を指定して評価
```

逆張り4条件は運用方針_v3 で**日足の判断に変わった**。分足での判定は根拠を失っている
（日足5年でプラスの条件が、5分足では符号が反転したため）。これに伴い
`--interval`（分足で見る指定）は削除した。

## 2. 取引の振り返り（決済したあと）

約定履歴の画像かCSV、または口頭で内容を伝えると起動する。

```
/trade-review
今日の取引を報告
決済したので振り返って
損切りになった
```

**必要な5項目**: 銘柄コード／エントリー日と価格／決済日と価格／株数／決済理由。
足りなければ聞き返す。発注した逆指値・指値、朝スコア、エントリー根拠もあると精度が上がる。

**返ってくるもの**
- 損益と保有営業日数
- ルール遵守の確認（順張りの必須2条件・見送り条件・禁止事項・逆指値を動かさなかったか）
- **決済水準の検証** — 保有中の最大含み益／含み損、決済後の値動きから
  「損切りが浅すぎたか」「利確が早すぎたか」を数字で判定
- `trades.csv` への記録（同じ日・同じ銘柄は二重に記録しない）

スクリプトを直接叩く場合。

```
python trade_review.py --code 8306 --entry-date 2026-07-29 --entry-price 3480 \
  --exit-date 2026-07-30 --exit-price 3525 --shares 100 \
  --stop 3341 --target 3724 --reason 利確 --rule 遵守 --save

python trade_review.py --stats     # 累積の勝率・平均損益・§9の判定基準
```

## 3. 朝の統合ブリーフィング（平日 8:00 想定）

```
python morning.py
python morning.py --format brief    # ランキングと決算一覧だけの短縮版
```

銘柄を主役にしたウォッチリストが返る。

1. 今日の地合い — 1〜3行。グループ別の内訳が要るときは overnight.py を叩く
2. ウォッチする銘柄 — 点数ではなく言葉で理由を出す
3. 見送り推奨 — テクニカルは通ったが運用方針に触れる銘柄。**上位5枠は消費しない**
4. 材料が出ている銘柄 — MA25の下。順張り対象外
5. 本日決算発表

見送りの判定は数値で決まるものだけをスクリプトが行う。残っているのは
§2 イベントフィルタ（決算当日・翌日）だけ。**禁止事項2（RSI 70超え）は v3 で撤回され、
`check_blockers` からも撤去した。** RSI は見送り理由ではなく、参考表示と §8 の記録項目になる。

**`score_rsi` の向きも v3 で反転させた。** v2 は RSI 65以上を減点し 75以上を0点に
していたが、実測は逆（日足5年で RSI70超の超過5日 +0.22〜+0.30%、5分足1ヶ月で勝率57.2%）。
配点は単調増加に直したが、幅は 5〜20点に抑えてある。候補はハードフィルタ通過時点で
ほぼ RSI 50以上に寄るため、実際に順位へ効く差は16〜20点の4点ぶん。運用方針 §4 が
「実取引20件で確定する」と段階を踏むことを定めているので、大きくは寄せていない。

**`quant_all_pass` の定義から `RSI < 70` を外した**（§7[5] の削除に対応）。
2026-08-07 より前の `picks_log.csv` の行は旧定義なので、`review.py` で
quant_all_pass 別に比較するときは境目に注意する。

各銘柄には **1単元の金額**（終値×100）を併記する。株価での足切りはしない。
アドバンテストのように1単元325万円の銘柄も候補には出すので、資金面の判断は本人が行う。

**ニュースは銘柄ごとに取得するが、採点しない。** 見出し6,569件で検証したところ
翌日リターンとの相関は最大 r=0.16(p=0.22) で、語の数え上げでは方向を判別できなかった。
「材料の裏付けは個別に確認してください」の取得だけを自動化している。

候補一覧には所属グループの**マクロ（朝スコア/閾値）を併記**する。これは材料として
並べているだけで、銘柄の点数には加算していない。マクロとテクニカルは互いのゲートに
せず、2本のトラックとして扱う。グループを持たない単独銘柄は `-` になる。

冒頭で東証の営業日判定を出す。休場日ならそこで終了する（J-Quantsのカレンダーを直接参照）。
同じ日に2回実行しても `picks_log.csv` は重複しない。

**注意**: 8:00 JST は 19:00 ET で、米国の時間外取引は 20:00 ET まで続く。引け後に決算が出た
銘柄はこの時点で動き切っていない可能性がある。冬時間はさらに1時間ずれる。

前夜の海外市場だけを見たい場合。

```
python overnight.py
python overnight.py --asof 2026-07-31   # 過去日の再現（時間外はスキップされる）
```

## 4. ユニバース更新（月1回程度）

```
python build_universe.py --codes nikkei225_codes.csv --max-price 5000 \
  --min-turnover 120 --keep-codes keep_codes.csv --max-universe 50
```

225銘柄を全部叩くので8〜9分かかる。日経225の構成銘柄が入れ替わったときは
`nikkei225_codes.csv` の更新が先。


## 設定ファイル

| ファイル | 中身 | 変更する場面 |
|---|---|---|
| `driver_map.yaml` | 連動グループの朝スコア・ニューストピック・感応度 | 指標や感応度を変えたいとき |
| `driver_tags.csv` | 銘柄 → ドライバー → 連動グループ | 分類を変えたいとき |
| `keep_codes.csv` | 条件を満たさなくても残す銘柄 | ウォッチ対象を足したいとき |
| `universe.csv` | 現在のユニバース74銘柄 | 通常は build_universe.py が生成 |
| `trades.csv` | 実売買の記録 | trade-review スキルが追記 |

### driver_map.yaml の項目に付けられるもの

| キー | 意味 |
|---|---|
| `ticker` | Yahooのシンボル。複数書くと平均で採点する |
| `感応度: -1` | その指標の**上昇がそのグループにとって逆風**（自動車の米10年債など） |
| `採点: false` | 変化率は表示するが**合計には入れない**。検証で効果が確認できていない指標を、消さずに材料として残すために使う |
| `急変閾値` | この%を超えたら★急変。平均だけでなく個別ティッカーも見る。全項目、発動率が10%前後になるよう実測から較正済み |

`driver_tags.csv` と `keep_codes.csv` を変えた場合、ユニバースの顔ぶれ自体は
`build_universe.py` を回さないと変わらない。分類やタグだけの変更なら再取得は不要。

## まだ自動実行していないもの

平日8:00の定期実行は**未登録**。Routine の作成に MCP ツールの承認が必要で、
セッションからは登録できなかった。設定値とプロンプトは `docs/morning-routine.md`
にまとめてあるので、それを使って登録すること。当面は手動で `python morning.py` を回す。

cron は `0 23 * * 0-4`（UTC評価のため、平日8:00 JST は日〜木の23:00 UTC）。

# 使い方（コマンド一覧）

## 0. 初回セットアップ

```
pip install -r requirements.txt
```

pandas・numpy・requests・PyYAML・openpyxl が要る。openpyxl は earnings.py が
JPXの決算発表予定日(Excel)を読むのに使う。

## 1. エントリー判定（買いたいときに都度）

**チャート画像を添付して、次のいずれかを送る。**

```
/entry-check 8306
```

またはスラッシュコマンドを使わず、自然文でも起動する。

```
8306を買いたい
このチャートどう？
エントリーしていい？
```

画像は日足と分足の2枚があると精度が上がる。1枚でも動く。画像なしでも日足の判定だけは出る。

**渡すと良いもの**
- 銘柄コード（4桁、または `285A` のような形式）
- チャート画像（日足＋分足）
- 現在値（画像に写っていれば不要）

**返ってくるもの**
- 順張り4条件（ORB・VWAP・出来高1.5倍・連動銘柄）の充足状況
- 逆張り4条件（ボリンジャー-2σ・RSI30・出来高急増・反発の陽線）の充足状況
- 禁止事項7項目のうち該当するもの
- 決算・会合のイベントフィルタ
- 損切り・利確の推奨値と、その銘柄のボラティリティに対する妥当性
- 判定できなかった項目

**返ってこないもの**: 「買うべき」「見送るべき」という結論。最終判断は本人。

数値だけ欲しい場合はスクリプトを直接叩いてもよい。

```
python entry_check.py 8306 --price 3571
python entry_check.py 8306 --interval 3m   # 逆張り条件を3分足で見る（既定は5分足）
```

逆張り4条件は**場中のエントリータイミングを見る条件**で、朝のスクリーニングには使わない。
Yahooに3分足は無いため、1分足（7営業日分）から合成している。5分足は1ヶ月分そのまま取れる。

## 2. 取引の振り返り（決済したあと）

約定履歴の画像かCSV、または口頭で内容を伝えると起動する。

```
/trade-review
今日の取引を報告
決済したので振り返って
損切りになった
```

**必要な5項目**: 銘柄コード／エントリー日と価格／決済日と価格／株数／決済理由。
足りなければ聞き返す。発注した逆指値・指値、朝スコア、エントリー根拠もあると精度が上がる。

**返ってくるもの**
- 損益と保有営業日数
- ルール遵守の確認（順張り4条件・禁止事項・逆指値を動かさなかったか）
- **決済水準の検証** — 保有中の最大含み益／含み損、決済後の値動きから
  「損切りが浅すぎたか」「利確が早すぎたか」を数字で判定
- `trades.csv` への記録（同じ日・同じ銘柄は二重に記録しない）

スクリプトを直接叩く場合。

```
python trade_review.py --code 8306 --entry-date 2026-07-29 --entry-price 3480 \
  --exit-date 2026-07-30 --exit-price 3525 --shares 100 \
  --stop 3341 --target 3724 --reason 利確 --rule 遵守 --save

python trade_review.py --stats     # 累積の勝率・平均損益・§9の判定基準
```

## 3. 朝のブリーフィング（平日 8:00 想定）

```
python briefing.py
python briefing.py --no-news         # ニュース取得を省く
python briefing.py --skip-overnight  # 海外市場の取得も省く（動作確認用）
```

`watchlist.csv` の**15銘柄を毎朝そのまま全部評価する**。絞らない。順位も付けない。
15銘柄の顔ぶれと選定理由は `docs/watch-portfolio.md`。

出るもの:

1. 今日の地合い（要約）— 1〜3行
2. **前提1 前夜の海外市場** — 指標ごとに変化率。複数ティッカーの項目は内訳まで。
   時間外で1%以上動いていればそれも。★は急変閾値超え
3. **前提2 グループ別のマクロ** — 7グループの朝スコアを、項目ごとの内訳付きで。
   何がプラスで何がマイナスか、感応度 -1 の項目、採点対象外の項目まで出す
4. **前提3 今朝のニューストピック** — 6トピックの方向判定と、根拠になった見出し・
   一致した語
5. 15銘柄の状態（一覧）— 終値・前日比・1単元・大きなトレンド・前日の足・今日の土俵
6. 土俵ごとの詳細 — マクロ／ニュース／決算／トレンド／前日の足／直近3日
7. 本日決算発表

### 何を出し、何を出さないか

朝に要るのは**前提情報**であって、エントリーの可否ではない。

**出さないもの**: RSI・出来高倍率・VWAP・ボリンジャー・ATR。
実際に買う瞬間に見れば足りる指標で、8時に見ても場が開くまでに変わる。
`/entry-check` 側にある。RSI は見送り理由になったときだけ理由文に現れる。

**定量的な部分**は2つに絞る。どちらも8時の時点で確定していて場中に変わらない。

- **大きなトレンドの向き** — MA25の20日傾き（↑↑/↑/→/↓/↓↓）、MA25・MA75との位置、
  直近10日の高値・安値の切り上げ／切り下げ、20日・60日の騰落率
- **直近の値動き** — 前日のローソク足を、陽線／陰線・実体の幅・上ヒゲ／下ヒゲの長さで。
  「上ヒゲが長い＝高値を買い上げたが押し戻された」まで書く。出来高は形の意味が
  変わるとき（1.5倍以上／0.6倍以下）だけ添える。あわせて直近3営業日の値動き

`watch_log.csv` には RSI・出来高倍率・ATR も記録している。表示していないだけで、
後から「どの土俵の銘柄が翌日どうなったか」を検証するときに使える。

**「今日の土俵」は新しい判定ではない。** 運用方針_v2 のどの節が適用されるかを
書き出しているだけ。

| 土俵 | 条件 | 意味 |
|---|---|---|
| 順張りの土俵 | 終値>MA25 かつ MA25が20日前より上 | §3-1 の4条件を場中に確認 |
| 押し目 | MA25は上向きだが終値がその下 | §3-2 の逆張り4条件が対象 |
| トレンド下向き | MA25が20日前より下 | 順張り対象外（禁止事項1） |
| 見送り | 決算当日/翌日、または RSI>70 | §2 イベントフィルタ / 禁止事項2 |

見送りの判定は数値で決まるものだけをスクリプトが行う。

### 「押し目」は深さを問わない

MA25から −2% の銘柄と −18% の銘柄が同じ見出しの下に並ぶ。
2026-08-04 に KOKUSAI（−17.9%）と村田（−19.6%）が別々の土俵に分かれたのを
きっかけに、深さで切る案を2つ実測した。**どちらも支持されなかった。**

15銘柄 × 約370営業日、押し目候補857件、保有5営業日:

| 案 | 残る | 外れる |
|---|---|---|
| 現行 | 857件 +0.68% 最大逆行 -4.04% | — |
| 終値>MA75 を追加 | 550件 **+0.50%** -4.38% | 307件 **+1.01%** -3.44% |
| 乖離 -8% 以内を追加 | 717件 +1.00% -3.31% | 140件 -0.95% -7.83% |

`終値>MA75` は**外す側のほうが成績が良く**、根拠にならなかった。

`乖離 -8%` は一見分かれるが、外れる162件の60%が半導体4銘柄
（フジクラ・KOKUSAI・SBG・村田）の 2026年6〜7月の**同一の暴落**だった。
相関0.5〜0.7の4銘柄に現れた1回の事象で、独立した観測ではない。
その分を除いた他11銘柄の65件は **+2.62% / 勝率60%** と、むしろ成績が良い。
ATR倍率で正規化しても、分かれ目は押し目の深さではなく銘柄のままだった。

結論として**フィルタは足していない**。かわりに **MA25乖離を一覧と各行に必ず出す**。
分類を細かくするより、乖離に見合った損切り幅と建玉を選ぶほうが実務に効く。
同じ −4% の損切りでも、乖離 −2% の銘柄と −18% の銘柄では刈られる確率が違う。

各銘柄には **1単元の金額**（終値×100）を併記する。株価での足切りはしない。

記録は `watch_log.csv` に15銘柄ぶん毎日残る。絞っていないので、
「どの土俵の銘柄が翌日どうなったか」を土俵別に後から測れる。

### 74銘柄のスクリーニング版（旧形式）

```
python morning.py
```

スコア順に5件へ絞る旧形式は `morning.py` として残してある。日々の
ブリーフィングには使っていない。記録先は `picks_log.csv` で、
`review.py` が読むのはこちら。ユニバース全体で何が起きているかを
見たいときに叩く。

**ニュースは銘柄ごとに取得するが、採点しない。** 見出し6,569件で検証したところ
翌日リターンとの相関は最大 r=0.16(p=0.22) で、語の数え上げでは方向を判別できなかった。
「材料の裏付けは個別に確認してください」の取得だけを自動化している。

候補一覧には所属グループの**マクロ（朝スコア/閾値）を併記**する。これは材料として
並べているだけで、銘柄の点数には加算していない。マクロとテクニカルは互いのゲートに
せず、2本のトラックとして扱う。グループを持たない単独銘柄は `-` になる。

冒頭で東証の営業日判定を出す。休場日ならそこで終了する（J-Quantsのカレンダーを直接参照）。
同じ日に2回実行しても記録は重複しない。

**注意**: 8:00 JST は 19:00 ET で、米国の時間外取引は 20:00 ET まで続く。引け後に決算が出た
銘柄はこの時点で動き切っていない可能性がある。冬時間はさらに1時間ずれる。

前夜の海外市場だけを見たい場合。

```
python overnight.py
python overnight.py --asof 2026-07-31   # 過去日の再現（時間外はスキップされる）
```

## 設定ファイル

| ファイル | 中身 | 変更する場面 |
|---|---|---|
| `driver_map.yaml` | 連動グループの朝スコア・ニューストピック・感応度 | 指標や感応度を変えたいとき |
| `driver_tags.csv` | 銘柄 → ドライバー → 連動グループ | 分類を変えたいとき |
| `watchlist.csv` | **毎朝ブリーフィングする15銘柄** | 顔ぶれを入れ替えたいとき |
| `keep_codes.csv` | 条件を満たさなくても残す銘柄 | ウォッチ対象を足したいとき |
| `universe.csv` | 現在のユニバース74銘柄（morning.py 用） | 通常は build_universe.py が生成 |
| `trades.csv` | 実売買の記録 | trade-review スキルが追記 |

### driver_map.yaml の項目に付けられるもの

| キー | 意味 |
|---|---|
| `ticker` | Yahooのシンボル。複数書くと平均で採点する |
| `感応度: -1` | その指標の**上昇がそのグループにとって逆風**（自動車の米10年債など） |
| `採点: false` | 変化率は表示するが**合計には入れない**。検証で効果が確認できていない指標を、消さずに材料として残すために使う |
| `急変閾値` | この%を超えたら★急変。平均だけでなく個別ティッカーも見る。全項目、発動率が10%前後になるよう実測から較正済み |
| `不感帯` | この%より小さい変化は**0点**にする。全項目、\|日次変化率\| の15%点で較正済み |

### 不感帯（2026-08-04 追加）

採点は「プラスなら +1 / マイナスなら -1」で、以前は不感帯が無かった。
そのため **ドル円 +0.01% が満点扱い**になり、数分違いの2回の実行で
半導体・AI関連が +3/+3（発火）から +1/+3（未達）に変わった。
閾値到達の可否が為替の0.02ポイントで決まっていたことになる。

一律 0.3% のような固定値は使えない。指標ごとに日次のブレ幅が10倍違うため、
固定0.3%だと**ドル円は80%の日が0点、SOX指数は8%しか0点にならない**。
較正は `急変閾値`（発動率およそ10%）と同じ考え方で、|日次変化率| の**15%点**にした。

各指標に日次σの5%の摂動を与え、閾値到達の可否がひっくり返る割合
（200試行。摂動は全案で共通にした対応のある比較）:

| | 不感帯なし | 10%点 | **15%点（採用）** | 20%点 | 30%点 |
|---|---|---|---|---|---|
| 半導体・AI関連 | 3.8% | 1.4% | **0.5%** | 1.2% | 2.0% |
| メガバンク | 1.3% | 0.5% | **0.3%** | 0.6% | 1.7% |
| 自動車 | 0.7% | 1.0% | **0.4%** | 1.0% | 1.7% |
| 商社 | 1.0% | 1.2% | **2.2%** | 1.2% | 2.1% |
| 海運 | 1.4% | 3.1% | **2.5%** | 1.3% | 0.4% |
| 平均 | 1.2% | 1.0% | **0.8%** | 0.8% | 1.1% |

発火率（朝スコアが閾値以上になる日の割合）:

| | 不感帯なし | 10%点 | **15%点** | 20%点 | 30%点 |
|---|---|---|---|---|---|
| 商社 | 23% | 18% | **16%** | 13% | 11% |
| 海運 | 24% | 18% | **13%** | 10% | 10% |
| 自動車 | 33% | 26% | **26%** | 26% | 20% |

問題が出た半導体・AI関連で最良（3.8%→0.5%）、メガバンクと自動車でも最良、
平均は20%点と同率。発火率の犠牲は20%点より小さい。

点が動いたときの振れ幅は **1.5〜2.1点 → 約1.0点**。
「+1 と −1 の間で飛ぶ」が「0 との間で動く」に変わるため半分になる。

**副作用**として発火率は下がる。朝スコアは順位付けに使わない表示専用の値なので、
「材料が揃っている」をより厳しく取る側に倒している。

**測り方の注意**: 摂動は案ごとに引き直さず全案で同じ乱数を使う。引き直すと
案の差より試行のばらつきが大きくなり、40試行では同じ設定でも半導体が
1.6% と 1.2% のように動いた。`tools/deadzone_calibrate.py` で再現できる。

### 直近セッションの欠落（2026-08-04 修正）

サンディスクが同じ朝の2回の実行で **+6.03% → −5.09%** と反転した。当初は
「米国の時間外による振れ」と書いたが**誤り**で、原因は取得側にあった。

Yahoo は直近営業日のバーを `close: null` のまま返すことがある。枠はあるのに
終値が入っていない状態で、確定値は `meta.regularMarketPrice` に入っている。
`overnight.fetch_series` はこれを落としていたため、**1営業日ぶん古い比較**をしていた。

```
補完あり  1288.03 / 1214.83 - 1 = +6.03%   （08-03 vs 07-31）← 正しい
補完なし  1214.83 / 1279.96 - 1 = -5.09%   （07-31 vs 07-30）← 1日ずれている
```

2026-08-04 08:00 JST の実測では、朝スコアが使う **24ティッカー中20本**で
直近セッションが欠けていた。Yahoo が2回の実行の間にバックフィルしたことで、
比較していた日そのものがずれていた。時間外の値動きは無関係だった。

`fetch_series` は `meta.regularMarketPrice` を補うようにした。引けたかどうかは
`currentTradingPeriod.regular.start`（次の取引時間帯を指す）と `regularMarketTime`
を比べて判定する。場中に走らせたときに未確定の値を掴まないための歯止めでもある。

### 残っている既知の歪み: ドル円

**8:00 JST はロンドンの 00:00** にあたる。ドル円の日次バーはこの瞬間に始まるため、
当日バーが0分ぶんしか進んでいない状態で前日終値と比べている。
実測でも ±0.01〜0.04% しか出ず、不感帯（0.04%）の境界上で揺れる。

市場のノイズではなく、**比べる2点の取り方の問題**。ドル円は朝スコアの
半導体・メガバンク・自動車の3グループに入っているが、事実上ほぼ常に
0点付近しか返していない。直すなら「24時間前との比較」に変える必要がある（未対応）。

`driver_tags.csv` と `keep_codes.csv` を変えた場合、ユニバースの顔ぶれ自体は
`build_universe.py` を回さないと変わらない。分類やタグだけの変更なら再取得は不要。

## 自動実行

平日8:00 JST に `briefing.py` が Routine で走る。cron は `0 23 * * 0-4`
（UTC評価のため、平日8:00 JST は日〜木の23:00 UTC）。
貼り付け用のプロンプトは `docs/routine-prompt.txt`、設定値は `docs/morning-routine.md`。

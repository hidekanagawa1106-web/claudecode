# 育休ノート

`parenting/` の記事を作る・保つスキル。**公開は Hide さんが手動で行います** ——
このスキルは note に投稿しません。

全体の流れと分担は `parenting/README.md` にあります。迷ったらそれが正。

## 毎回読むもの

- `parenting/docs/persona.md` — 誰に、どんな声で。**ここと矛盾する文は書けません**
- `parenting/docs/outline.md` — 構成と分量
- `parenting/docs/rules.md` — 禁止表現。**書いたあと必ず照合する**

## やること別の手順

### A. リンクを作る（「リンク作って」「商品リスト更新した」）

```bash
python parenting/rakuten_affiliate.py
```

終わったら `status` の内訳を報告する。`guess` が残っていたら
`parenting/out/candidates.md` を読み、採用中のものが妥当かを1件ずつ見て、
**怪しいものだけ**を挙げる。全件を列挙しない。

`gone` / `not_found` があれば、代替候補をキーワード検索して提案する。
`products.csv` を勝手に書き換えない —— 商品の決定は Hide さんの領分です。

### B. 本文を書く（「下書き書いて」「本文お願い」）

1. `python parenting/build_note.py` で骨組みを出す
2. `parenting/out/note_draft.md` の `<<< ... >>>` を埋める
3. 埋めたものを同じファイルに書き戻す

書くときに守ること:

- **`comment` の実体験から離れない。** 種に無い事実を足さない。
  情報が足りない商品は、埋めずに `<<< 要ヒアリング: なぜ買ったか >>>` と残して、
  最後にまとめて質問する。**捏造で埋めるくらいなら空で返す**
- **一人称。** 「私は」「うちは」で書く。「〜と言われています」を使わない
- **1商品3要素まで**（困った場面 / どう変わったか / 誰には要らないか）。
  それ以上書くとスペック紹介になります
- **`◎` は全体の3分の1まで。** 全部必須の記事は信用されません
- **「買わなくてよかったもの」を手を抜かずに書く。**
  ここが弱いと記事全体が売り込みに見えます。リンクは貼らない
- **効能を断定しない**（治る・防ぐ・改善する・必ず・最強）。
  主語を自分と自分の子に固定すれば大体避けられます
- 価格をベタ書きするなら「執筆時点で約◯円」と添える
- 絵文字なし。見出しは短く

### C. 公開前チェック（「公開前チェック」「チェックして」）

`docs/rules.md` §6 のチェックリストを1項目ずつ実際に確認する。
**目視ではなく grep で確認できるものは grep する**（禁止表現、PR表記）。

出力は、**引っかかった項目だけ**を該当箇所付きで挙げる。
全項目に「OK」を並べない。何も無ければ「全項目通過」の1行でいい。

`products_resolved.csv` に `ok` 以外の status が残っていたら、
そこで止めて報告する。リンク切れのまま公開させない。

### D. 生存チェック（「リンク切れ確認」「定期チェック」）

```bash
python parenting/rakuten_affiliate.py --check
```

差分が無ければ**「変化なし」の1行で終える。** それ以上書かない。

差分があったら:
- リンク切れ → 代替候補を検索して提案する
- 価格変動 → 記事本文に価格を書いている箇所を grep して、該当箇所を挙げる

## 出してはいけないもの

- **実体験にない事実。** これが一番の禁止事項です。
  `comment` に無いことを「たぶんこうだろう」で書かない
- 医療・発達・安全性の断定（睡眠、うつぶせ寝、離乳食は特に）
- 妻・子・勤務先が特定できる記述
- 「これさえ買えば」型の煽り、「完全ガイド」「必需品まとめ」的な見出し
- 楽天以外のASPリンク（note の規約違反になります）
- PR表記を消した下書き
- チェック結果の全項目列挙

# 取引の振り返り

取引が終わったあとに、記録を残しながら検証する。

## この振り返りで一番価値がある部分

損益そのものはHideさんが既に知っている。**検証する価値があるのは、決済したあとに
価格がどう動いたか**である。これは日足から機械的に判定でき、感想ではなく数字で出せる。

- 損切りで終わった → その後戻したなら、損切りが浅すぎた可能性がある
- 利確で終わった → その後さらに伸びたなら、利確が早かった可能性がある
- 保有中に利確ラインへ到達していたのに利確で決済されていない → 指値の置き方の問題
- 保有中の最大含み益と実現損益に開きがある → 伸びを戻している

ここを毎回押さえることが、勝ち負けの感想を並べるより効く。

## 手順

### 1. 取引の内容を読み取る

入力は画像・CSV・口頭のいずれか。**次の5つが揃わないと分析できない。**

- 銘柄コード
- エントリー日と価格
- 決済日と価格
- 株数
- 決済理由（損切り／利確／手動）

画像なら約定履歴の表を読む。CSVならそのまま読む。**足りない項目は推測せず、聞き返す。**

あるとより良いもの（無くても進む）:
- **発注した逆指値・指値の値** — これが無いと §5 の損切り水準を検証できない。
  v3 で検証の中心になった項目なので、無ければ一度は聞く
- その日の朝スコアと内訳
- エントリー根拠（順張りの必須2条件が揃ったか／逆張り4条件か）
- ルール通りだったか、外れたならどの条件を飛ばしたか

### 2. スクリプトで分析して記録する

```
python trade_review.py --code 8306 --entry-date 2026-07-29 --entry-price 3480 \
  --exit-date 2026-07-30 --exit-price 3525 --shares 100 \
  --stop 3341 --target 3724 --reason 利確 \
  --score "朝スコア+3（米10年債+1/ドル円+1/米銀+1）" \
  --basis "順張り必須2条件" --rule 遵守 --memo "..." \
  --rsi-daily 62.1 --rsi-intraday 71.3 --dev-ma5 0.8 --dev-ma25 1.4 \
  --entry-time 10:35 --orb-gap 0.4 \
  --refs "VWAP上/出来高1.1倍/連動○" \
  --discipline "その日1銘柄目・根拠は朝スコア・後付けなし" --save
```

`--save` を付けると `trades.csv` に追記する。**同じ日・同じ銘柄が既にあれば追記しない。**

**v3 の記録項目（`--rsi-daily` 以降）は必ず渡す。** 空欄で保存すると
その取引は §8 の月次集計から抜け落ちる。スクリプトが未入力の列を警告するので、
警告が出たら聞き直して入れ直す。

出力されるもの:
- 損益率・損益額・保有営業日数
- **損切り・利確の水準の検証（§5）** — エントリー時点の日足ATR(14)と、
  発注した損切り幅がその何倍だったか。1.5〜2.0倍の外なら理由付きで指摘される。
  リスクリワードが §5 の目安1.75倍を下回る場合も指摘される
- 保有中の最大含み益／最大含み損、利確・損切りラインへの到達有無
- 決済後5営業日の値動きと、そこから言えること
- システムの候補（`picks_log.csv`）に出ていたか、裁量エントリーか

**ATR は `entry_check.py` と同じ定義**（前日終値までで確定した日足ATR(14)）を使う。
エントリーした朝に `/entry-check` が表示していた数字と同じもので後から評価される。

### 3. ルール遵守を確認する

運用方針 §8 は「ルール通りだったか。外れていたならどの条件を飛ばしたか」を記録するよう
定めている。**スクリプトでは判定できないので、本人に聞く。**

聞くべきこと（**運用方針_v3** に照らす。v2 の4条件必須では聞かない）:

- 順張りの**必須2条件**（ORB上抜け・日足MA25の上）は揃っていたか
- 見送り条件に当たっていなかったか（14:00以降／ORB高値から+1%以上）
- 禁止事項（下降トレンドの途中で買う）に触れていないか
- 損切り・利確は**エントリー直後に発注し、あとから動かさなかったか**（§0）
- 持ち越した場合、ポジションサイズを**最悪ギャップから**逆算したか（§5）

**v3 で追加された記録項目**（ここが無いと v3 の変更の当否を後から判定できない）:

- 日足RSI(14) と 場中RSI(14)
- 日足MA5・MA25からの乖離率
- エントリー時刻（前場／後場）
- ORB高値からの乖離率
- 参考条件（VWAP・場中の出来高・連動）の充足状況
- **v2 から削除された規律の該当状況** — その日すでに何銘柄目か、根拠は何だったか、
  理由を後から付けていないか

削除された5項目（寄り付き直後の飛びつき／1日複数銘柄／トレンドラインのみ／
理由の後付け／急騰の追いかけ）は、**ルールから外れただけで「やってよい」ではない。**
判定はしないが、ここで必ず聞いて残す。

答えを `--rule`（遵守／一部逸脱／逸脱）と `--violation` に入れて記録する。
**これが記録されていないと、§8 の「条件が揃っていた取引と揃っていなかった取引の成績差」が
永久に測れない。** 曖昧なまま「遵守」にしない。

### 4. レポートを書く

## 出力フォーマット

```
【取引の振り返り】<コード> <銘柄名>  <エントリー日> → <決済日>

■ 結果
  損益 ±X.XX%（±X,XXX円） 保有N営業日  決済理由

■ ルール遵守（運用方針_v3）
  順張りの必須2条件: 揃っていた / 欠けていた条件
  見送り条件: 該当なし / 14:00以降・ORB+1%以上
  禁止事項: 該当なし / 下降トレンドの途中で買う
  削除された規律の該当状況: その日何銘柄目か / 根拠 / 後付けの有無
  逆指値・指値: エントリー直後に発注したか、動かさなかったか
  → 遵守 / 一部逸脱 / 逸脱

■ 損切り・利確の水準（§5 = 日足ATR(14)の1.5〜2倍）
  エントリー時の日足ATR(14) XXX円（終値比 Z%）
  発注した損切り幅は ATRのN倍 … §5内 / 狭い / 広い
  リスクリワード N倍（§5 の目安は1.75倍）

■ 決済水準の検証
  保有中の最大含み益・最大含み損
  利確ライン・損切りラインへの到達有無
  決済後N営業日の値動きと、そこから言えること

■ 次に変えるとよいこと
  1〜3点。数字で裏付けられるものに限る

■ 記録
  trades.csv に追記（通算N件）
  累積: 勝率X% / 平均損益±X% / §9の判定基準に対する現在地
```

## 注意

- **1回の取引の勝敗はほぼ運で決まる。** 個別の取引から強い教訓を引き出そうとしない。
  「利確が早かった」と言えるのは数字が示したときだけで、負けた取引に後付けの理由を
  与えるのは、v2 の禁止事項6（理由の後付け）そのものになる。v3 でルールからは
  外れたが、ここで見張る対象であることは変わらない。
- **ルールを守って負けた取引を、失敗として扱わない。** 逆に、ルールを破って勝った取引は
  問題として扱う。運用方針が測ろうとしているのは損益ではなくルールの有効性である。
- 改善案は**数字で裏付けられるものに限る**。「もっと慎重に」のような助言は書かない。
- ロジックや配点の変更を提案してもよいが、**勝手に変更しない**。判断はHideさん本人。
- **損切り幅が §5 の範囲外だったことを、負けた原因にしない。** 幅が基準どおりでも
  負けるし、外れていても勝つ。ここで見ているのは執行がルールに沿っていたかだけで、
  損益との関係は件数が貯まってから `--stats` の
  「損切り幅 × ATR」の欄で見る。
- 累積の集計は `python trade_review.py --stats` で出す。20取引未満のうちは
  勝率のブレが大きく判断材料にならないため、その旨を必ず添える。
  `--stats` は v3 の記録項目が入っていれば **日足RSI別**（§4 の RSI70超え撤回の検証）と
  **損切り幅 × ATR 別**（§5 の検証）も出す。RSI70以上が20件たまるまでは
  条文を確定しない、と §4 が定めている。

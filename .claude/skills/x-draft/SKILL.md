# 投稿の下書き

コピペしてそのまま投稿できる状態で、**2本提案します。**
**在庫（`x/stock.md`）に書くのは、Hideさんが承認したものだけです**（2026-08-21 変更）。
**投稿はHideさんが手動で行います** —— このスキルは投稿しません。

**日付も投稿枠（朝・夜）も割り当てません。** Hideさんは好きなときに好きな順で使い、
自分で思いついた投稿も混ぜます。こちらで日程を組んでも意味がありません。

## 手順

### 1. 読む

**毎回読むもの**

  （過去11本は最高記録なので、あの数字を基準にすると判断を誤ります）
- `x/docs/persona.md` — **設定。ここと矛盾する投稿は書けません**
- `x/docs/formats.md` — 型（＝**どう書くか**）
- `x/docs/content.md` — **内容（＝何について書くか）。実際の143本から抽出した
  登場人物・テーマ・決め台詞の作り方。型が合っていても中身がここから外れると
  別人の投稿になります**
- **`x/docs/claims.md` — ネタ帳（C001〜）。主張の材料。番号で指定されたらここを引く**

### 1.5 ★ 主張が重なることは問題にしない（2026-08-18・Hideさんの指示）

> 主張が重なることは今後も問題にしなくて良い。
> **むしろアカウントのコンセプトをはっきりさせるためにも、主張はそんなに増やさず、
> いくつかを表現と型を変えて出し直すのが現実的。**

**同じ主張を、型と表現を変えて何度出しても構いません。**

**ネタ帳は `x/docs/claims.md`（C001〜C095）。** 考えるときの参考に使います。
**出どころも、過去に投稿したかどうかも区別していません**
——同じネタを型と表現を変えて何度も出す前提だからです。
**そこに無い主張を書いてはいけない、という縛りではありません。**

**「C023で型4作って」のように番号で指定されることがあります。**

**以下を一切やらないでください。**

- 「承認済みの◯◯と主張が重なります」という指摘
- 「続けて出さないこと」「1週間／2週間／2ヶ月空けてください」という注意
- 「同じ主張なので1本だけ使う」「残りは却下へ」という整理
- 重複を理由に在庫の本数を割り引いて数えること

タイムラインの性質上、同じ主張が同じ人に何度も届く確率は低く、
**繰り返すこと自体がこのアカウントの立場を作ります。**
実測1位の型4「本当に強いのはこういう人」も、系統としては
何度も書いている「頑張りすぎる人へのゆるし」です。

**引き続き見るのは"型の重複"だけです**（同じ型が続くと見た目で飽きられる）。
主張ではなく骨格グループのバランスを見てください。


### 2. 型を選ぶ（在庫のバランスで決める）

**骨格グループのルールが最優先です**（`formats.md` の冒頭）。

| グループ | 型 |
|---|---|
| A | 型1・型2・型3・型5（骨格が同じ。実績はここ） |
| B | 型4 対比リスト |
| C | 型7 会話だけ |
| D | 型8 短文 |
| **E** | **型9 助詞切り**（実験枠。**在庫1本まで**） |

**グループEは「文を助詞の途中で切って、答えを自己リプに置く」型**です。
`formats.md` の「型9候補: 助詞切り」に**穴埋めテンプレートと見本**があります。
**Hideさんが「助詞切りで」「途中で切る形で」と言ったらこれです。**
締めが無い型なので、**グループAの書式（『』・同意誘導）を持ち込まないこと。**

**日付ではなく在庫を見て決めます。** Hideさんがどの順で使うか分からない以上、
「今日はA、明日は非A」という組み方は成立しません。**在庫の中でAと非Aが
半々になっていれば、どこから取っても非Aが混ざります。** これが飽き対策の本体です。

- **`x/stock.md` の「承認済み」だけを数える。** Aが多ければ非Aから、
  非Aが多ければAから補充する。**「予約済み」は数に入れません**
  （もう出る先が決まっていて、Hideさんが選べる在庫ではないため）。
  **未承認の下書きは在庫ではありません**（2026-08-21 の運用変更。後述）
- **在庫に1本も無いグループがあれば、そこを最優先で埋める**
- **型4（グループB）は実測があるのに未使用。** 在庫を切らさない
- **`x/posts.csv` の直近3本と同じ型は避ける**。ただし **posts.csv に載って
  いない投稿がある前提で見てください** —— Hideさんは先の日付に予約投稿を
  仕込むことがあり、それはレビューが返るまでどこにも現れません。
  「記録が無い＝投稿していない」と決めつけないこと

**⚠ 型2・型3・型5を続けて出すときは、箇条書きの素材を変えてください**
（2026-08-21）。この3つは**読者から見ると同じ形**です（`formats.md` の見た目クラス）。
**名詞（資格・希望条件）／作業（議事録を送る）／セリフ（「厳しそうです」）**の
どれかに割り振って、直近の在庫と被らせないこと。
骨格そのものは崩さないでください。**この形が実測で最強（6.65倍）です。**

**⚠ 型より先に、主張の形を見てください**（2026-08-18の失敗から）。

**主張が「AだからB、BだからC」の連鎖になっているときは、
型7（会話だけ）と型8（短文）を選ばないこと。**
会話劇は場面を見せる型なので因果を運べず、短文は連鎖が「〜ので」に
圧縮されて読み飛ばされます。**連鎖は断言型か型2の地の文で書きます。**

在庫のバランスより**主張の形が優先**です。バランスのために型7を選んで、
3案まとめて「わかりづらい」で没にしました（`formats.md` の型7）。

型の中身の方針（`winners.md` の検証項目）:

- **型4（対比リスト）を切らさない** —— 9月・12月とも1位。1272万の実績。在庫0本
- **型4はまず「頑張りすぎる人へのゆるし」テーマで。** 転職テーマの型4は
  同じ骨格で1700分の1でした
- **型3（人物観察）が枚数の稼ぎ頭**（36本）。青学卒の営業（28才）は使い回してよい
- **型2を意識的に増やす** —— 導線の本命候補。決め台詞なしのリスト形式も有効
- **型1を出しすぎない。** 48本で中央値536、最も書かれていて最も伸びていない型です
- **型1を出すなら、質問・場面・他人の失敗から入る形。** 「自分の失敗ドラマ必須」は
  実測で否定されました（`formats.md` の型1の訂正）
- **教訓を語るだけの形**は出さない（実測最下位）
- **型3の箇条書きは必ず「作業」で書く**（姿勢で書くと14倍沈みます）
- **他人が登場しない断言の形は出さない**（実測で最下位）
- **1〜3行目で「読者に何を予測させるか」を作る。** 自分の失敗はその一手段で、
  謎の提示や期待させてから落とす形でも代替できる（`winners.md` の外部検証）

### 3. ソースを選ぶ

`sources.md` の優先順位どおり。**素材帳が空でも止まりません。**

**テーマを選んだら、3つで判定します**（`sources.md` の「伸びるテーマの条件」）。

- **「確かに」と思える発見があるか**
- **「それは違う」と反論が出る余地があるか**（全員が頷くテーマは、言う必要がない）
- **「自分の場合は」と言いたくなるか**

**狙いは "意見を言いたくなる" であって "反発" ではありません。**
返信数が多い投稿は実測で伸びていないので、絡まれにいく形にしないこと。

1. **★ネタ帳** — `x/docs/claims.md`（C001〜C095）から主張を選ぶ。**ここが既定です。**
   - **番号で指定されたら、その主張をそのまま使う**（「C023で型4作って」）
   - 指定が無ければ、**在庫に足りない型に乗る主張**をここから選ぶ
   - **出どころも、過去に投稿したかも見ません。** 型と表現を変えて出し直す前提です
   - **1つの主張を2つの型で出しても構いません**
2. **過去投稿の焼き直し** — `posts.csv` の伸びた行からテーマを取り、別の型で出し直す。
   **間隔は気にしません**
3. **スワイプ** — `swipe.csv` から構造とテーマを借りる。
   **言い回しとエピソードそのものは借りない**
4. **時事** — `topics.md` の在庫から。賞味期限を確認する。
   **1行目に置ける形にならないなら使わない**
5. **実体験** — `episodes.md` に在庫があれば優先的に

**議論を狙う回は `x/docs/debates.md`**（D1〜／N1〜）から取ります。
`claims.md` とは性格が違います —— **claims は言いたいこと、debates は割れること。**
前者は同意で回り、後者は議論で回ります（`formats.md` の「議論系の締め」）。

**2本とも時事にしないこと。** 時事は多くて2本のうち1本です。
**賞味期限のある素材は在庫に寝かせられません** —— 期限が近い時事で作ったら、
その旨を在庫に書き添えて、早く使うよう伝えてください。

### 4. 設定と突き合わせる

`persona.md` を見て、次の3点だけ確認します。**細かい整合性は追いません** ——
新卒期のエピソードが増えても、同じ上司が何度も名言を言っても構いません。

- **骨格を壊していないか**（元リクルート／現ベンチャー面接官／社会人10年／
  新卒時は顧客を持つ職種）。ここが崩れると説得力の出どころが消えます
- **既に使った一言を再利用していないか。** 決め台詞は読者が覚えています
- **特定リスク**。会社名・部署名・製品名・個人名を出していないか

### 5. 書く

1本につき、次の形で出す。

```
──────── 【グループ】A
【型】型2 面接官の暴露 ／【ネタ】C023 ／【ソース】T002（賃上げ）＋ swipe #12 の構造

（投稿本文。コピペする範囲。ここにリンクは入れない）

──── 1stリプの橋渡し案（バズを確認してから使う）
（funnel.md の公式どおり、橋渡しの1〜2行だけ。
 リンクと広告表記はHideさんが付けるので書かない）

【狙い】この型・このソースで何を検証するか（1行）
```

**グループAの書式**（詳細は `formats.md` と `voice.md`）:

- **『』の決め台詞を独立行に置く。** 前後に空行。投稿の重心はここ
- **締めは同意誘導。既定は「〜よね。」**（実測76本・月内相対1.05で最多）。
  「〜なんだよな。」は12本、**「〜からね。」は0.40と最も弱い**ので既定にしない。
  疑問形にもしない。**私は「なんだよな」を選びすぎる癖があります**（`voice.md` 10番）
- シグネチャ構文「などあるが、とくに良いのは、」を型どおりに使う
- 学歴・年齢を出す（型3）
- 改行は1〜2文ごと

**B・C・D にAの書式を持ち込まないこと。** 『』も同意誘導の締めも要りません。
持ち込むと結局Aに見えて、変化をつけた意味が消えます。

**全グループ共通**:

- **本文にリンクを入れない**
- 絵文字なし、ハッシュタグなし
- **他人が必ず登場する**（**型4を除く**。型4で人物を出すと0.1倍）
- **主語を具体化する**（若手社員 → 早稲田卒の25才 ／ メンタル弱い人 →
  怒られたら3日引きずる人）。年齢3.3倍・学歴2.1倍。**型4だけは人物ではなく
  行動を具体化する**（`voice.md`「具体性の出し方」）
- **述語はセリフにする。** 要約された教訓は誰でも書けますが、
  セリフはその場にいた人しか書けません

**自分を上げる話にしない。** Hideさんが登場するときは、常に失敗している側か
教わる側です（過去11本に武勇伝は1本もありません）。

**時事を使う場合は入口だけ。** 1行目で触れて、2行目以降はいつもの型に戻る。
中身までニュース解説にしないこと。

### 6. 現実性を確認する（書いたあと必ず。**ここが一番よく失敗します**）

**構造を満たすために、現実に起きないことを書かないでください。**
実際に2本つぶしています。

- **その決め台詞、本当に言う人がいるか。** 型に空きがあるからといって台詞を
  発明しない。「二段の引きを作るために不自然な質問を挟む」で1本つぶしました
  （実例:「その子の名前の由来って知ってる？」← そんなことを聞く上司はいない）
- **型2の「意外な1つ」が、業界の常識に反していないか。**
  逆張りのために事実を曲げない。**Hideさんは実際の面接官です。**
  業界の人が読んで「それは違う」となる主張は、意外性以上に信用を削ります
  （実例:「ベンチャーでビジョン共感を落とす」← ベンチャーはむしろ重視する）
- **語り手のポジションを崩していないか。** 型ごとに立場が決まっています
  （`voice.md` の表）。**型2だけは判断する側**で、ここで困る側・弱者側に立つと
  型の権威が消えます（実例:「候補者から聞かれて困る質問は」← 自社が答えられないと
  自己申告する形になる。「通す人がよく聞くのは」なら成立する）
- **誇張していないか。** 間を持たせるために数字や状態を盛らない
  （実例:「1on1で15分ほぼ黙り込んだ」← 15分は現実にありえない長さ）
- **箇条書きと締めが同じ軸に乗っているか。** 3〜4項目と総括が別の話をしていると、
  読者は「で、何が言いたいの」で止まります（実例: 逆質問の案）
- **判定は「意外か」ではなく「意外で、かつ本当か」。** 両方満たせないなら
  その素材は捨てて、別の切り口を探してください
- **型2は素材バンクか出典から書く。** `formats.md` の素材バンクを見て、
  無ければ WebSearch で調べる。**想像で書いた4本のうち3本が却下されました**
  （通ることもありますが、外したときに信用を削ります）

### 7. 承認されたものだけ在庫に書く（2026-08-21 変更）

**下書きはチャットに出すだけです。`x/stock.md` に書くのは、
Hideさんが承認したものだけ。**

**以前は「要レビュー」に入れて寝かせていました。やめた理由が3つあります。**

- **そのまま通った下書きは1本だけ**（型2 求人票）。未承認のものを在庫に
  数えていたので、**撃てる本数を実態より多く見ていました**
- **要レビューに出口がありませんでした。** 8本のうち5本はHideさんが修正まで
  したのに承認とも却下とも言われないまま止まっていました
- **寝かせるほど劣化します。** 規定が更新されると古い下書きは無効になります
  （型5の3稿は「視点の選択」の規定が増えた時点でまるごと使えなくなりました）。
  ネタは `claims.md` にあるので、**捨てても書き直せます**

手順はこうなります。

1. 2本をチャットに出す（コピペできる形で。理由の説明は各案3行まで）
2. Hideさんが**承認したものだけ**「承認済み」に追記する。
   **修正版が返ってきたら、必ずそちらを本文にする**
3. **却下されたら下書きは残しません。**
   代わりに**却下の理由を `formats.md` か `voice.md` の該当セクションに書く。**
   ここだけが資産です。`stock.md` 末尾の「却下」表には1行だけ残す
4. 判断が返ってこなかったものは、**次の `/x-draft` の時点で消えたものとして扱う。**
   もう一度出したければ、そのときの規定で書き直したほうが速い

- **既存の在庫を消さない。** 却下されたものは「却下」の表に理由付きで移す
- **「予約済み」の項目には触らない。** Xに予約投稿として仕込まれていて、
  こちらからは状態が見えません
- 末尾の「**いま足りないもの**」を、追記後の在庫で書き直す
- **日付・曜日・朝夜の見出しを付けない**

投稿後に `/x-review` が実績を記録するとき、このファイルを見れば
「何を狙って出したか」が分かります。記録できたら「使用済み」へ移します。

### 7.5 テーマ指定の依頼には3案出す

**Hideさんから「◯◯という内容でポストを作って」と言われたときは、
1本ではなく3案**出してください（2026-08-16の指示）。

**言い回しを変えた3案では意味がありません。骨格を変えます。**

```
案A  型4 対比リスト   … 判断基準を渡す。拡散狙い
案B  型7 会話だけ     … 場面を見せる。返信狙い
案C  型8 短文        … 短く言い切る。流し読みでも残る
```

効く要素は型ごとに違うので（`formats.md` の冒頭）、**骨格が違えば
読者に届く経路も変わります。** 言い回しだけの差では選ぶ意味がありません。

**3案とも出します。** どれか1つに絞る必要はありません。
ただし**在庫に書くのは承認されたものだけ**です（手順7）。
残り2案は、後で使いたくなったら**そのときの規定で書き直します。**
**主張が重なることは問題にしない**（下記の恒久ルール）ので、
3案は**別々のタイミングで撃てる3本**として扱ってください。

### 8. 添える

2本を出したあと、短く3つ。

- **使ったネタの番号**（C023 など）と、**この2本で何を検証しているのか**、
  **追加後の在庫の内訳**
  （例:「B・Dを1本ずつ補充。在庫はA3・B1・C1・D1。型7と型8は初回なので数字を見る」）
- **設定に新しく足した事実があれば明示する**（あれば `persona.md` に追記が要ります）
- 在庫のうち**賞味期限のあるもの**（時事ネタ）があれば一言。
  ここだけは「早く使ってください」と言う理由があります

## 出してはいけないもの

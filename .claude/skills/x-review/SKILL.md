# 投稿の振り返り

`/trade-review` と同じ役割です。**この仕組みで唯一、資産が増える工程**なので、
面倒でも毎回通してください。ここを飛ばすと、ただのAI文章生成器になります。

## 入力

X アナリティクスのスクショ、または数値の口頭報告。**24時間以上経った投稿だけ**
記録します。数時間しか経っていない数字を記録すると、時間帯の比較が崩れます。

スクショから読み取るもの:

- インプレッション
- いいね / リポスト / 返信 / ブックマーク
- **プロフィールへのアクセス**（副次的な導線）
- **1stリプ側のインプレッション** ← リプ投稿のアナリティクスを別途開く
- **リンククリック** ← ASP管理画面の数字が最も正確
- フォロー増（アナリティクスに出なければ聞く）

**リプ側のインプレッションとリンククリックが揃わない場合は、必ず聞き返して
ください。** この2つが無いと導線が測れず、記録する意味が半分無くなります。
推測で埋めないこと（未指定なら未計測として記録され、率の集計から外れます）。

## 手順

### 1. 記録する

投稿ごとに1コマンド。

```
python x/x_review.py --add --date 2026-08-11 --slot 朝 \
  --format 型1 --episode A007 --hook "冒頭1行をそのまま" \
  --impressions 420000 --likes 3800 --reposts 410 --replies 26 \
  --bookmarks 55 --profile-clicks 2100 \
  --reply-impressions 180000 --link-clicks 340 --followers-delta 18
```

同じ日・同じ枠が既にあれば追記しません。上書きするなら `--force`。

**`--format` は正直に付けてください。** 型1のつもりで書いても、
出来上がりに失敗のドラマが入っていなければ、それは `型1崩れ` です
（実測で40倍の差がある別物なので、混ぜると型1の評価が壊れます）。
同様に、型3で箇条書きが「姿勢」になっていたら `型3-姿勢` と書き分けてください。

### 2. 集計を見る

```
python x/x_review.py
```

出力の見方。**インプレッションから読み始めないでください。**

- **導線のブロック** — リプ到達率 × リプCTR = 総合導線率。**ここから読む**
- **型ごとの表** — 総合導線率の降順。3本以上溜まった型だけ出ます
- **「伸びたのに導線が抜けた投稿」** — ここが一番の学びです。
  数字が大きくても**失敗として扱う**

### 3. 言語化する

数字を並べるだけでは資産になりません。次の3つに答えてください。

- **伸びた投稿の1行目は、沈んだ投稿の1行目と何が違ったか**（構造の差として書く。
  「内容が良かった」は答えになっていません）
- **導線が抜けたのは、リプ到達とリプCTRのどちらか**（`funnel.md` 参照。
  到達が低ければ本文とリプの断絶、CTRが低ければ橋渡しの文の問題）
- **今日の結果で、次に変えることは何か**（1つだけ。複数変えると原因が分からなくなります）

**1本の結果で結論を出さないこと。** 同じ型が3本溜まるまでは「観測中」と書く。
X の配信はばらつきが大きく、1本の当たり外れは運の範囲です。

### 4. winners.md を更新する

`x/docs/winners.md` の該当セクションに追記する。既存の記述と矛盾する結果が出たら、
**古い記述を消さずに「◯月◯日時点で反転」と併記**してください。
いつ何が変わったかが後から効いてきます。

3本以上溜まって明確に劣後している型があれば、「効かなかった型」に理由付きで移す。
`formats.md` からは消さない（後で条件が変われば戻せます）。

### 5. episodes.md を更新する

使った素材を「使用済みの素材」へ移し、`使用:` 欄に日付と枠を書く。
**素材は削除しない** —— 別の型で切り直せば再利用できます。

## 報告の形

集計の出力をそのまま貼ってから、言語化した3点を書く。
数字の解説はしないでください（Hideさんも同じ表を見ています）。

# エントリー前チェック

「今この銘柄を買いたい」というときに、運用方針_v3 に照らして判断材料を整理する。
条文は `docs/運用方針_v3.md`（Notion「運用方針_v3」と同内容）。

## やること / やらないこと

**やる**: ルールに対して現在の状態がどうかを並べ、損切り・利確の推奨値を出す。
**やらない**: 「買うべき」「見送るべき」という結論は出さない。最終判断はHideさん本人。

これは運用方針の大前提「本ルールは投資助言ではない。最終判断は自己責任」と、
キオクシア用ブリーフィングの「断定的な買い/売り推奨は記載しない」に従う。

## 手順

### 1. 入力を確認する

必要なもの:
- 銘柄コード（4桁または `285A` のような形式）
- チャート画像（あれば。無ければ日足の判定だけで進める）
- 現在値（画像から読める場合はそれを使う。不明なら直近終値で評価する）

コードが分からない場合は `company_master.csv` を検索して特定する。

### 2. 数値をスクリプトで取得する

```
python entry_check.py <コード> [--price <現在値>]
```

出力されるもの:
- トレンドの位置（MA5/25/75・パーフェクトオーダー・RSI・出来高倍率・直近5日の騰落）
- 当日の場中（VWAP・現在値との位置関係・当日高安・直近5分の出来高倍率）
- 禁止事項(§4)の該当状況
  ※スクリプトはまだ v2 の 1・2・7 を判定する。**2（RSI70超）は v3 で撤回済み**なので、
    出力に出ても抵触として扱わず、参考値として読む
- 値動きの大きさ（日中値幅・ギャップ幅の直近14日実測）
- §5 に沿った損切り・利確の推奨値と妥当性評価
- 決算（直近の開示・翌営業日の予定）
- 連動グループと同グループ銘柄の直近の動き

**数値は必ずこのスクリプトから取る。チャート画像から読み取った数値で判断しない。**
画像は解像度や描画設定で値がずれるため、根拠にはAPIの値を使う。

### 3. チャート画像を読む

画像があれば、スクリプトでは取得できない情報を補う。

- **オープニングレンジ**（9:00〜9:15の高値・安値）と、現在値がそれを上抜けているか。
  **上抜けているときは「ORB高値から何%離れているか」も出す。**
  22営業日の実測では、乖離が大きいほど成績が悪い（0.25〜0.5%で60分後 +0.120%、
  1〜2%で -0.022%、2%超で -0.063%／引けまでで -0.189%）。
  **+1%を超えていたら見送る**（v3 の見送り条件）。v2 の禁止事項§4-7「急騰銘柄を
  後から追いかける」を、この具体条件に置き換えたもの。
  — これはAPIでは取れない。Yahooの1分足は寄り付き直後が欠けることがあり、
  2026-07-31の実測ではフジクラが09:19開始でORB窓のバーが1本も無かった。
  **条件1は必ず画像から読む。**
- **板・歩み値**（画像にあれば）
- 直近の高値・安値、意識されていそうな価格帯
- 上ヒゲ・下ヒゲの形状
- スクリプトが出したVWAP・現在値が画面と一致しているか
  — 配信の遅延は未計測。食い違えば画面の値を採用し、その旨を明記する

画像から読めない項目は「画像からは判定できません」と明記する。推測で埋めない。

#### 大引け際はYahooの分足に存在しない

寄り付きが欠けるのと同じ問題が、引けにもある。15銘柄×22営業日で正規の終値
（J-Quantsの日足）と突き合わせた実測:

- **最終バーが15:20で終わる日が282/327件（86%）** — 大引けと板寄せが丸ごと無い
- 最終バーの値が正規の終値と一致したのは 36/327件（11%）だけ
- 差は平均 0.275%、最大 1.486%（2026-07-28 の富士通で 3,645 対 3,700）

**14:55以降の判定に分足を使わない。** 引け際の値動きも、引け値を起点にした計算も、
このデータではできない。画面（証券会社の正規データ）を見る。

同じ理由で、**画面のRSIとスクリプトのRSIは一致しない。** 楽天の分足RSIは
短期9・長期14だが、期間を揃えても値は合わない（2026-08-06のフジクラ15:30で
画面 57.50/39.17 に対しこちらは 41.7/43.4）。**閾値を運用ルールにするなら、
画面の値を基準に決める。** こちらの計算値で決めると、画面上の別の状態を指す。

#### クロスヘア位置の値に注意

**OHLC行とMA値は「クロスヘアが乗っているローソク足」の値であり、最新とは限らない。**
チャート下部の黄色いラベル（`< 09:15 >` `< 08/03 >` など）が、いまどの足を指しているかを示す。

- OHLC行の終値と価格パネルの現値が食い違う場合、**現値と前日比を正**とする
- 前日終値は `現値 − 前日比` で検算する。OHLC行と合わなければ、OHLC行は別の足の値
- MA値もクロスヘア時点のもの。現値との大小を比べるときは、**MAの傾き**（上向き/下向き/横ばい）を
  目視で併せて見て、クロスヘアが古い位置なら割り引く

矛盾を見つけたら黙ってどちらかを採用せず、「OHLC行は別足の値の可能性」と一行添える。

#### 出来高の構造的スパイク

以下は板寄せ（注文の一括約定）による出来高で、**シグナルではない**。平均を取る母数からも外す。

| 時間帯 | 内容 |
|---|---|
| 9:00〜9:05 | 前場寄り付き |
| 12:30〜12:35 | 後場寄り付き |
| 14:55〜15:00 | 大引けの成行集中 |

これらのバーだけが1.5倍を超えていて直後が通常水準に戻っている場合、
**条件3は「数値上は満たすが意味を持たない」と明記する。**

`entry_check.py` はこの3区間を平均から除外している。ただしYahooの1分足は
寄り付き直後が欠けるため、前場寄りのバーはそもそも取れていないことが多い。

### 4. ルールに照らして整理する

照らす先は **運用方針_v3**（`docs/運用方針_v3.md` / Notion「運用方針_v3」）。
v2 から条件が変わっている。**v2 の4条件必須で判定しない。**

**順張り（§3-1）— 必須は2つ**

| 条件 | 判定元 |
|---|---|
| 1. オープニングレンジブレイク | **チャート画像のみ**（下記の理由でAPIは使えない） |
| 2. 前日終値時点の日足MA25より上 | スクリプトが日足から計算 |

**参考（見るが、欠けても見送りにはしない）**

| 項目 | 判定元 | 扱い |
|---|---|---|
| VWAPより上か | スクリプトが計算 | 条件1とほぼ同時に成立し、独立した情報がない |
| 場中の出来高倍率 | スクリプトが直近5分の倍率を出す | **多いほど良いとは扱わない** |
| 連動銘柄の方向 | `driver_map.yaml` の連動確認先 | 実測では情報を持たなかった |

**見送る条件（いずれかに当たれば入らない）**

- **14:00以降の新規エントリー**
- **ORB高値から+1%以上離れている**

**RSIは順張りの条件ではない。** §4 の参考項目として水準を見る。
使うのは**日足のRSI(14)**（`entry_check.py:260` が日足終値から計算する）。
**低いほど不利、高いほど順行しやすい**という向きで読む（§4の検証メモ）。

**検証メモ（2026-08-05、15銘柄・22営業日・5分足）**

条件を重ねるほど成績が落ちた。

| | 勝率 | 超過60分 |
|---|---|---|
| 条件1のみ | 53.4% | +0.037% |
| 条件1+2（VWAP） | 53.5% | +0.039% |
| ＋出来高1.5倍 | 45.3% | -0.085% |
| **v2の4条件すべて** | **35.5%** | **-0.333%**（95%CIがゼロを外れる） |

出来高スパイクは方向を持たない。買いが集まる瞬間と利確の売りが出る瞬間の区別がつかない。
同じ理由で大陽線・大きな足も直後の成績が悪かった（実体+0.3%超で -0.099%、
直近20本比2.5倍超の足で -0.102%）。

**逆張り4条件（§3-2、すべて必須）** — 順張りが揃わない日の補完。
**v3 で判定する足が日足に変わった。場中の分足では使わない。**

| 条件 | 判定 |
|---|---|
| 1. 日足ボリンジャー -2σ タッチ | 日足安値 ≤ 下限バンド（20日・2σ） |
| 2. 日足RSI 30以下 | 14日 |
| 3. 日足の出来高急増 | 20日平均の1.5倍以上 |
| 4. 反発の陽線1本確定 | 実体が直前の下落陰線の70%以上／出来高が直前以上／上ヒゲが実体の30%以下 |

**日足に限定する理由**: 時間軸で符号が反転した。RSI30以下は日足5年で
+0.64% [+0.12, +1.13] だが、5分足では -0.209% [-0.392, -0.020]。
下降MAからの大幅下方乖離も、日足 +0.61% に対し5分足 -0.938%（勝率32.4%）。
**日単位では「行き過ぎからの反発」でも、分単位では落下の途中**でしかない。

`entry_check.py --interval` の分足判定は、この変更で**根拠を失っている**。
分足で計算した逆張り条件を、エントリー可否の根拠に使わない。

**禁止事項（§4）** — v3 で1項目に減った。

1. **下降トレンドの途中で買う**（日足MA25の下、かつMA25が下向き）

**参考（禁止ではない。記録して後で検証する）**

- **RSIの水準** — 高いほど順行しやすい。低い状態での順張りに注意する

**RSI 70超えの禁止は v3 で撤回された。** 3つの独立したデータで否定側だった
（74銘柄・日足5年 +0.22%／15銘柄・日足5年 +0.30%（5年すべてプラス）／
15銘柄・5分足 勝率57.2%）。5分足で7区分に切ると単調増加する
（〜30で -0.206%・45.4% → 80以上で +0.357%・63.8%）。
計算式と期間の4通りすべてで同じ向きだった。

**v2 から削除された5項目**（寄り付き直後の飛びつき／1日複数銘柄／トレンドラインのみ／
理由の後付け／急騰の追いかけ）は、**ルールとして判定しないが「やってよい」わけではない。**
状況を聞いて `trade-review` の記録に残す。急騰の追いかけは、上の見送り条件
「ORB高値から+1%以上」に具体化されている。

**イベントフィルタ（§2、スコアより優先）**

- 決算発表の当日・翌日 → ポジション半分以下、または見送り
- FOMC・日銀会合の当日 → 寄り付き直後は入らない
- 決算・会合をまたぐ持ち越しはしない

### 5. 損切り・利確を提示する

**v3 でスイングの損切りは日足ATR(14)の1.5〜2倍になった。** 一律 -4% は使わない。
利確は損切り幅の1.75倍が目安。デイトレ枠（高ボラ -2〜3%／大型株 -0.6%）と
逆張り（-1.5%）は v2 のまま。

スクリプトの出す実測ボラティリティと突き合わせ、次の2つは必ず伝える。

- **損切り幅が日中値幅より狭い場合** — 方向が合っていてもノイズで刈られる
- **平均ギャップが損切り幅に近い場合** — 寄り付きで逆指値を飛ばされる

**-4%/+7% を ATR 基準に変えた理由**: 10日以内にどちらへ先に届くかを測ると、
損切りが利確の1.5倍の頻度で当たった（母集団で -4%到達36.0% 対 +7%到達23.2%）。

#### 持ち越すならギャップから逆算する

逆指値は寄り付きのギャップを止められない。モメンタム銘柄では **-4%を超える下ギャップが
2.17%の頻度**で発生し、最悪 -23.0% だった。**枠B・Cのポジションサイズは、
損切り幅ではなく想定される最悪ギャップから逆算する。**

#### 上値抵抗との距離を必ず見る

利確目標を出しっぱなしにしない。**現値から最も近い上値抵抗**までの距離を出し、
損切り幅と比べる。抵抗になるのは日足のMA25・MA75、直近高値、節目価格。

- 「最も近い抵抗までの距離 < 損切り幅」なら、**リスクリワードが悪い位置**と明記する
- 利確目標が抵抗の向こう側にあるなら、「抵抗突破が前提」と書く

#### 押し目の目安

分足MA5・MA25、日足MA5 の価格と、現値からの乖離率を出す。

- 乖離が小さい（〜2%程度）→ 待つコストが低い
- 乖離が大きい（5%以上）→ 現在地は高値掴みゾーンである旨を明記

運用方針 §0 のとおり、**エントリー直後に逆指値・指値で発注し、あとから動かさない**。
ポジションサイズは損切り幅から逆算する。**ただし持ち越す枠B・Cは、上記のとおり
損切り幅ではなく最悪ギャップから逆算する。**

## 出力フォーマット

```
【エントリー前チェック】<コード> <銘柄名>  <現在値>

■ 結論として確認すべきこと
  揃っている条件 / 欠けている条件 / 抵触している禁止事項 を各1〜2行

■ 順張りの必須2条件
  1. ORB上抜け     ○ / × / 画像からは判定できません（○ならORB高値からの乖離 +X%）
  2. 日足MA25の上  ○ / ×（乖離 +X%）

■ 見送り条件
  14:00以降か / ORB高値から+1%以上離れているか

■ 参考（判定には使わない）
  VWAP … ／ 場中の出来高倍率 … ／ 連動銘柄 …
  日足RSI XX.X（高いほど順行しやすい。低い状態での順張りに注意）
  ※画面のRSIとは値が一致しない。閾値で判断するなら証券会社の表示を基準に

■ 禁止事項の該当
  （下降トレンドの途中で買う に当たるか。なければ「抵触なし」）
  （v2から削除された規律の該当状況も、状況を聞いて記録に残す）

■ イベント
  決算・会合の該当状況

■ 損切り・利確（エントリーするなら）
  損切り -X% → ○○円 ／ 利確 +Y% → △△円
  この銘柄の日中値幅は平均Z%。損切り幅は日中値幅のN倍で（妥当／狭い／広い）
  ポジションサイズは損切り幅から逆算してください

■ 判定できない項目
  （画像にもAPIにもない情報を明記）
```

## 注意

- **条件が揃っていない場合、それを揃ったことにしない。** 運用方針は「揃わなければ何もしない」
  と定めており、条件を甘く読むことがいちばんの害になる。
- 数値が取得できない項目は「データ取得不可」と明記し、判定に含めない。
- 「買い時です」「絶好の水準です」といった断定表現は使わない。

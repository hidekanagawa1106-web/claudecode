# 競合の分析

転職系で伸びている投稿から**構造だけ**を取り出して、自分の素材で使える型にします。

## 前提

X API を使わない運用なので、**投稿はHideさんが持ち込みます**（スクショまたはURL）。
自動収集はしません。x.com は認証なしで取得できないので、URLだけ渡されて中身が
見えない場合は、スクショか本文の貼り付けを頼んでください。**推測で分析しないこと。**

週1回、伸びていた投稿を5本ほど持ち込む運用を想定しています。

## 絶対にやらないこと

**文章を写さない。** 取るのは構造だけです。表現をなぞると、他人の体験談を自分の
一人称で語ることになります。転職系は業界が狭く、見ている人が見ています。

取っていいもの: 情報の出す順番、1行目の作り方、どこで引きを作っているか、
問いかけの置き方、長さ。

取ってはいけないもの: 言い回し、比喩、固有のフレーズ、エピソードそのもの。

## 手順

### 1. 分解する

1投稿につき、次を出す。

- **1行目が何をしているか**（一言 / 数字 / 断言 / 逆説）
- **2行目以降の情報の順番**（状況→感情→構造、など）
- **どこで読者を止めているか**
- **問いかけの有無と、その形**
- **なぜ伸びたと考えられるか** —— ここは**構造で説明する**。「内容が良い」は
  分析になっていません。同じ内容を別の順番で書いたら伸びなかったはず、
  と言える形まで落とす

### 2. 記録する

`x/swipe.csv` に1行追記する。列は
`date,account,format,hook,structure,why_it_worked,impressions,likes,url`。

`hook` は1行目を**要約して**入れる（そのまま写さない）。
`structure` は「一言→状況→感情→構造→問い」のように矢印でつなぐ。

### 3. 型にするか判断する

`x/docs/formats.md` の既存の型5つと照合する。

- 既存の型の変種 → **追加しない**。既存の型の「注意」欄に知見を1行足すだけ
- 明確に別の構造 → 新しい型として追加する。番号を振り、**効く理由と注意を必ず書く**

**型を増やしすぎないでください。** 8個を超えたら、実績の無い型から削ります。
型が多いと `/x-draft` の選択がぶれて、どの型も3本に届かなくなります。

### 4. 素材と突き合わせる

新しい型を足したら、`x/episodes.md` の未使用素材を見て、
**その型で使えそうな素材があるか**を確認する。無ければその型は当分使えないので、
そう伝えてください（`/x-mine` でその方向を掘る材料になります）。

## 報告の形

分析した本数、追加した型（あれば）、既存の型に足した知見。
分析の全文は貼らない —— swipe.csv にあります。

# 育休ノート（楽天アフィリエイト）

育休中に買ったものを紹介しつつ、育児準備の進め方を書く note 記事を作り、
そこから継続的に成果が出る状態を保つための一式。

対象読者・記事構成・守るルールは `docs/` に、機械でやる部分はスクリプトに
分けてあります。

---

## 1. 何を機械にやらせて、何を人がやるか

**この分担がこのプロジェクトの本体です。** 逆にすると失敗します。

| 工程 | 誰が | 中身 |
|---|---|---|
| 商品を決める | **Hide さん** | 実際に使ったものしか書けない。ここは代替不能 |
| 実体験を1行ずつ書く | **Hide さん** | `products.csv` の `comment`。記事の原材料 |
| 商品の特定・リンク生成 | **スクリプト** | `rakuten_affiliate.py`。楽天APIが affiliateUrl を返す |
| 価格・レビュー・画像の取得 | **スクリプト** | 同上。手で転記しない |
| 記事の骨組み・PR表記・並び順 | **スクリプト** | `build_note.py` |
| 紹介文を書く／全体を整える | **Claude** | `comment` を種に本文化。`docs/persona.md` の声で |
| 規約チェック（薬機法・PR表記） | **Claude** | `docs/rules.md` §6 のチェックリストで通す |
| note に貼って公開 | **Hide さん** | 公開判断は人が持つ |
| 公開後の腐り監視 | **スクリプト** | `--check` で廃番・価格変動を検知 |
| 差し替えとリライト | **Claude** | 検知された分だけ直す |

境目は一つだけ覚えておけば十分です ——
**「事実」と「体験」は Hide さん、「転記」と「整形」は機械、
「文章化」と「照合」は Claude。**

紹介文をスクリプトに書かせないのは、そうするとスペック紹介になり、
スペック紹介は読まれず、読まれない記事は1円も生まないからです。

---

## 2. 準備（最初の1回だけ）

楽天側は登録済みとのことなので、値を環境変数に入れるだけです。

```bash
export RAKUTEN_APP_ID=...         # https://webservice.rakuten.co.jp/app/list
export RAKUTEN_ACCESS_KEY=...     # 同じ画面のアプリ情報
export RAKUTEN_AFFILIATE_ID=...   # https://webservice.rakuten.co.jp/account_affiliate_id/

pip install -r ../requirements.txt
```

`~/.zshrc` に書いておくと毎回打たずに済みます。
**この3つは絶対にコミットしない**（`.gitignore` 済み）。

あわせて先に済ませておくもの:
**楽天カードの発行、または楽天銀行口座の楽天会員リンク登録。**
これが無いと報酬が3,000円で頭打ちになります（`docs/rules.md` §4）。

## 3. 記事を作る（4ステップ）

### Step 1 — 商品リストを埋める（Hide さん）

`products.csv` を開いて埋めます。ヘッダーのコメントに書き方があります。

最低限、埋めるのはこの3つ:

- `name` — 自分の言葉での呼び方
- `comment` — **実体験。「何が起きて、これがどう効いたか」を一文**
- `timing` / `must` — いつ要るか、どのくらい要るか

商品ページのURLが分かるなら `rakuten_url` に貼る。分からなければ `keyword`
だけでいい（あとで候補から選べます）。

**`comment` に時間をかけてください。** ここの密度がそのまま記事の質になります。
「便利だった」ではなく「夜中2時に片手が塞がった状態で」まで書く。

### Step 2 — リンクを作る（スクリプト）

```bash
python parenting/rakuten_affiliate.py
```

`products_resolved.csv` に、アフィリエイトURL・価格・レビュー・画像URLが
入った状態で出ます。楽天APIは `affiliateId` を付けて投げると
`affiliateUrl` をそのまま返すので、リンクを手で組む工程は丸ごと不要です。

`status` の見方:

| status | 意味 | やること |
|---|---|---|
| `ok` | URL/コードで一意に特定できた | なし |
| `guess` | キーワード検索の1件目を採用した | `out/candidates.md` を見て確認 |
| `gone` | 指定した商品ページが消えている | 代わりの商品を探す |
| `not_found` | キーワードで何も出なかった | `keyword` を変える |

`guess` が残っていたら `out/candidates.md` を開いて、正しいものの商品URLを
`products.csv` の `rakuten_url` に貼って再実行。`ok` に変わります。
**公開前に `guess` を全部潰すこと。**

### Step 3 — 下書きを組んで、本文を書く（スクリプト → Claude）

```bash
python parenting/build_note.py
```

`out/note_draft.md` に骨組みが出ます。`<<< ... >>>` が本文を書く場所で、
各商品には Step 1 で書いた `comment` が種として埋まっています。

ここで Claude に投げます:

```
/parenting-note 本文を書いて
```

`docs/persona.md`（誰に、どんな声で）、`docs/outline.md`（構成）、
`docs/rules.md`（禁止表現）を読んだうえで、`<<< >>>` を埋めます。
出てきたら **必ず自分で読んで直す。** 実体験の細部は本人にしか直せません。

### Step 4 — 規約チェックして公開（Claude → Hide さん）

```
/parenting-note 公開前チェック
```

`docs/rules.md` §6 のチェックリストで通します。
通ったら `out/note_draft.md` を note に貼り、`out/links.md` を見ながら
Cmd+K でリンクを当てて公開。

**PR表記（冒頭・末尾）は消さないでください。** 景表法の要件です。

## 3.5 スプレッドシートに価格・料率を入れる

商品リストをGoogleスプレッドシートで管理している場合。

```bash
python parenting/rakuten_affiliate.py     # 価格と料率を取る
python parenting/sheet_paste.py           # 貼り付け用の2列を出す
```

`out/sheet_DE.tsv` を D2（最初のデータ行）に貼れば、価格列と料率列が一度に埋まります。
`products.csv` の `id` をシートの行番号に合わせてある（`r02` = 2行目）ので、
値の無い行も空行として出力され、行ズレが起きません。

**楽天の短縮リンク（`a.r10.to/...`）はそのまま `rakuten_url` に貼れます。**
スクリプトがリダイレクトをたどって商品を特定し、結果を `.url_cache.json` に
覚えるので、2回目以降はネットワークなしで解決します。

料率（`affiliateRate`）はAPIが商品ごとに返す実数値です。ジャンル横断で
2〜4%が中心ですが、店舗設定で高いものがあります。**料率の高い商品を
記事の目立つ位置に置くと成果が変わります。**

## 4. 記事を増やす

1本目が公開できたら、商品を増やすのではなく**記事を分けます。**

- 商品が20点を超えたら、セクションを切り出して別記事にする

  ```bash
  python parenting/build_note.py --section 家事削減
  ```

  `out/note_draft_家事削減.md` に別ファイルで出ます。本記事の下書きは潰れません。
  （本文を書き込み済みの下書きは上書きされません。作り直すときだけ `--force`）

- 記事同士を内部リンクで繋ぐ。回遊が増えるほど成果は上がります
- 「育休の手続き編」「復帰編」など、商品が出てこない記事も混ぜる。
  そちらが入口になって、商品記事に流れる形が一番長持ちします

楽天の成果条件は**クリック後24時間以内にカゴ・89日以内に購入**で、
クリックした商品以外を買っても成果になります。だから記事の仕事は
「この商品を買わせること」ではなく **「楽天に行かせること」**。
リンクを1本置いて終わりではなく、読者が動く場所に自然に置くほうが効きます。

---

## 5. 公開後（ここが「収益を生み続ける」の実体）

記事は放っておくと腐ります。廃番・型落ち・価格改定でリンクが死にます。

```bash
python parenting/rakuten_affiliate.py --check
```

前回との差分だけ出ます —— リンク切れと、10%以上の価格変動。
月1回で十分です。Claude Code の定期実行に載せられます:

```
/loop 30d /parenting-note リンクの生存チェック
```

あわせて年2回、以下を回すと記事が寿命を延ばします。

- 切れた商品を差し替える（`products.csv` を直して Step 2 から）
- 「買わなくてよかったもの」を実績で更新する
- 楽天お買い物マラソン／スーパーSALE の時期に X から再告知する
  （`x/` のスキル群がそのまま使えます）

`docs/rules.md` §5 のとおり、note は検索に弱いプラットフォームです。
成果が乗ってきたら、同じ `note_draft.md` を自前ブログにも置くことを勧めます。
下書きはプラットフォーム非依存の素材として作ってあります。

## ファイル

```
parenting/
  products.csv           ← Hide さんが埋める。ここが入口
  products_resolved.csv  ← スクリプト出力。リンク付き商品データ
  rakuten_affiliate.py   ← 楽天API。リンク生成と生存チェック
  build_note.py          ← 下書きの骨組みとリンク対応表を組む
  docs/
    persona.md           ← 誰に、どんな声で書くか
    outline.md           ← 記事の構成と分量
    rules.md             ← note規約・景表法・薬機法・楽天規約
  out/
    note_draft.md        ← note に貼る下書き
    links.md             ← リンク対応表（Cmd+K 用）
    candidates.md        ← guess の候補一覧
```
